┌──────────────┐   API (JSON)   ┌───────────────────────────┐
│ apps/editor  │ ─────────────▶ │ apps/api（Worker・Hono）   │
│ 編集画面      │ ◀───────────── │  ・ログイン（メール）      │

│               │ ─────────────▶ │  ・公開ページ（HTML）→ R2  │

## フォルダ

| 場所 | 中身 | 元 |
|---|---|---|
| `packages/core/` | データの形（DATA_SPEC v4）、テンプレートの組み立て、配置（付いていく先・伸び縮み）、改行の規則、公開用 HTML の描画、① お店の情報（品・出す月） | `experiments/layout/playground30/model/`・`build.mjs` のページの組み立て・`tools/lib` |
| `apps/editor/` | 編集画面。部品ごとのファイル（文字・写真・選ぶ/動かす・セクション・品・保存/公開・道具の並び…）。保存先は差し替えられる（`LocalStore`＝IndexedDB／`ApiStore`＝サーバー） | `experiments/layout/playground30/app.js` を分けたもの |
| `apps/api/` | Cloudflare Worker（Hono）。ログイン・権限・下書き・版・写真・公開・公開ページの配信。D1・R2 | 新しく作る |
| `tools/verify-audit/` `tools/verify-claudeai/` | 本物の操作で確かめる E2E（Python・Playwright） | 今のまま |
| `.github/workflows/` | push のたびに単体試験・E2E を走らせる | 新しく作る |

`experiments/`（試験台1〜30）は凍結。新しい作業は `packages/`・`apps/` で行う。古いものは後で消す（git の履歴に残る）。

## 大事な決め方
- **公開は「編集画面が描いた HTML を送る」。** 配置と改行はブラウザで測って決まるので、サーバーで描き直さない。プレビューと公開ページが同じ形になる（D2）
- **日付で変わる所（出す月・販売）**：公開ページの HTML には全部の品を入れておき、出す・出さないの切り替えはページの小さなスクリプトで日付を見て行う……ではなく、**毎日 0 時に Worker の Cron が「今日の出し入れ」で描き直しを頼む**。描き直しは Cloudflare Browser Rendering で編集画面の描画を使う（v1 の M4 で作る。それまでは公開のたびに描く）
- **下書きの保存は「今の形」まるごと**（DATA_SPEC 4.9）。D1 に JSON で持ち、版番号で同時の書き込みを見分ける（B4）
- **編集画面は今の素の JavaScript のまま**（作り直さない）。esbuild で1つの HTML にまとめ、今の確認スクリプトがそのまま走るようにする
- 写真の縮小・位置情報の削除は、ブラウザで行ってから送る（C2）。HEIC はブラウザで JPEG に変える

## 環境
| 名前 | 用途 |
|---|---|
| local | `wrangler dev`（ローカルの D1・R2）。試験はここで走る |
| staging | main に入ったら自動で出す（E1）。サブドメイン `*.staging.<ドメイン>` |
| production | タグを打ったら出す |

Cloudflare のアカウント・API トークン・ドメインは、ユーザーが用意する（DECISIONS.md の「待ち」）。それまでは local だけで進める。

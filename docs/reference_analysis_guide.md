# 参考サイト分析の手順書（芦屋みっけ）

③層のテンプレート・オーダーメイドを作るときに、他のWebサイトを「どう参考にするか」を定めた手順書。別プロジェクト（Pawly）で運用していた「参考サイト分析→模倣方式」の考え方を取り入れ、次の2点を芦屋みっけ向けに変えている。

- **参考にする範囲**：構造の数値はそのまま使い、色・フォント・装飾は性格だけを取る（1章）
- **使用量（燃費）**：分析をチャット＋Chromeから、Claude Code＋スクリプトに移す（3章・4章）

作り方（データの形、材料、編集ツール）は `handoff_note_web_system_01.md`・`02.md` に従う。本書が扱うのは、参考サイトから何をどう取り出して設計書（SPEC.md）にするかまで。

---

## 1. 参考にするもの・しないもの

この区分は、各テンプレートの SPEC.md の「持ち込んでよいもの・持ち込まないもの」章と一致させる（例：wa-01 は SPEC 11章）。

| 区分 | 対象 | 扱い |
|---|---|---|
| **そのまま持ち込む（値ごと使う）** | 構造の数値（位置・大きさ・余白・グリッド・コンテンツ幅・セクションの高さ・ヘッダーの高さ）、**色の値**、**書体**、文字の段（大きさ・太さ・行送り・字間）、罫線・横棒・ピルのボタンのような一般的な形 | 灰色の階調・無料の書体・一般的な形は、それ自体が誰かの権利の対象ではなく、写真・文章・店名が違えば複製にはならない。色や書体を選び直すと参照元の質が失われる（v1 の反省）。SPEC の表の値どおりに組む |
| **持ち込まない** | 写真・イラスト、文章・コピー、ロゴ（丸い印など）、店名・人名・商品名・価格・住所、業種固有の言葉 | 実測レポートに見出しの文字列が出るのは、セクションの対応づけのためだけ。写真は自分たちで別に用意する（参照元と同じ写真も使わない） |

- 値（色・書体・数値）まで持ち込んでよいのは、上の理由（一般的な要素は権利の対象でない）による。差別化は写真・文章・店名で行う。以前の版（v1）のように色・書体を選び直すと、参照元の「整って見える」質が失われるため、選び直さない
- **参照サイトの分析では、文字と写真だけでなく、色のついた面（帯・地・札・線）も測って取り込む。** 背景色だけの帯・区切り・罫線は「見えている構造」なのに、文字要素の照合では出てこない（例：FV下の News帯＝#333 の横帯は、要素の照合では一致扱いだが、両側塗りの画素比較で初めて「参照元にあり・再現に無し」の差として現れた／clone §2.3・2026-09-23）。`ref-mask.mjs` の COLLECT は img・文字に加えて、透明でない背景色・境界線を持つ要素を「面」として拾う（位置・大きさ・色・不透明度・角丸・重なり順つき）。ただしセクションの地の色・全面スクリムは `section.background` で塗るので、生成側（clone-gen）で「全幅かつ高さのある面」を除いて二重にしない
- 参考サイトは別業種でもよい。取り出した構造と性格を、芦屋みっけの業種の意味に置き換える
- 1テンプレートにつき参考サイトは原則1つ。複数を混ぜると「どれにも似ていないが、どれとも半端に似ている」ものになりやすい。部分的に別サイトを使う場合は、どのセクションにどのサイトを使ったかをSPEC.mdに書く

## 2. 固定セクション（暫定）

参考サイトのセクションは、次の固定セクションに**対応づけるだけ**にする。参考サイトに合わせてセクションを足したり削ったりしない。対応するものがないセクションは「対応なし→新規設計」とし、その参考サイトの構造と性格だけを根拠に設計する。

| # | セクション | 中身（データの出どころ） | 備考 |
|---|---|---|---|
| 1 | ファーストビュー | 代表写真、店名、キャッチコピー | |
| 2 | お店の物語 | 店主の言葉、こだわり（①の物語） | |
| 3 | メニュー・商品 | ①のリスト（メニュー→括り→品）。業種で名前が変わる | 代表だけ／全部、は②で選ぶ（02の3.6） |
| 4 | おすすめ | ①のリストのうち「おすすめ」ラベルの品 | 3と兼ねてもよい |
| 5 | ギャラリー | 写真 | |
| 6 | スタッフ・講師・医師 | ①のリスト | 業種による |
| 7 | よくある質問 | ①のよくある質問 | |
| 8 | 注文・予約の案内 | ①の外部サービス（通販、テイクアウト、予約） | 02の5B |
| 9 | お店の情報 | 住所、営業時間、定休日、電話、地図（①と連動） | |
| 10 | お問い合わせ | フォーム（使う店だけ） | 01の5.5 |
| 11 | お客様の声（任意） | 実在するお客様の声をオーナーが載せる場合のみ | 医療・治療院では使わない。作った口コミは載せない |
| 共通 | ヘッダー、フッター、ページ移動のメニュー | | フッターに芦屋みっけ掲載店の表示（02の5A） |

- どのセクションも0件〜N件で崩れないこと。中身が空なら非表示
- 背景色の交互パターンは「固定の順番」ではなく「表示中のセクションの中で何番目か」で決める（非表示のセクションがあってもずれないように）
- この一覧は、Studio級のデザインでの検証（01の7.1）と最初の数件の制作を経て確定させる

## 3. 流れ（セッションを分ける）

Claudeは返事のたびに会話全体を読み直すため、1つの会話を長く続けるほど1回あたりが高くつく。STEPごとに会話を分け、前のSTEPの結果は短いファイルで渡す。

| STEP | 場所 | Claudeの役割 | 入力 | 出力 |
|---|---|---|---|---|
| 0 参考サイトの選定 | チャットでも可 | 候補出し | 業種・雰囲気の希望 | 参考URL（1つ） |
| 1 撮影と実測 | Claude Code | **スクリプトを実行するだけ**（軽いモデルで可） | 参考URL | `refs/<サイト>/`（report.md、全体像、切り抜き） |
| 2 分析と設計 | Claude Code（新しい会話） | 判断の中心。上位のモデルを使う | report.md、全体像2枚、必要な切り抜きだけ | `templates/<ID>/SPEC.md` |
| 3 実装 | Claude Code（新しい会話） | SPEC.mdだけを根拠に作る。分析はやり直さない | SPEC.md | テンプレート |
| 4 確認 | Claude Code | **スクリプトの結果を読むだけ** | 成果物、置換表、写真リスト | 問題の一覧（なければ1行） |

### STEP 1 撮影と実測
```
node tools/ref-capture.mjs <参考URL> refs/<サイト名>
```
- PC（幅1440）とスマホ（幅390）で、ページ全体を最後までゆっくりスクロールしてから撮る（遅れて読み込まれる写真と、スクロールで現れる演出を出し切るため）
- 同意画面など画面を覆う要素は**押さずに隠して**撮る
- `report.md` の**警告**を必ず見る。警告があれば6章の対処に従う

### STEP 2 分析と設計
- 読むのは `report.md`（数KB）と `overview-pc.jpg`・`overview-sp.jpg`（縮小済み）の2枚から始める
- 切り抜き（`sec-*.jpg`）は、**数値では判断できないセクションだけ**開く。目安は合計6枚まで。開く理由をSPEC.mdに一言書く
  - 開く：写真と文字の重なり方、あしらい、余白の空気感、縦書きなど
  - 開かない：列数・余白・文字の大きさなど、レポートの数値で足りるもの
- やること
  1. 参考サイトの各セクションを2章の固定セクションに対応づける
  2. 構造の数値を確定する（1章の「そのまま使う」）
  3. 色・フォント・装飾を性格の言葉にし、自分たちの値を選ぶ（1章の「選び直す」）
  4. 業種語の置換表を作る（参考サイトの見出し・ナビに出てくる語、固有名）
  5. 隣接衝突の対策を決める（全面写真のセクションが続く箇所に、色帯・余白などのどれを入れるか）
  6. 「対応なし」のセクションだけを新規設計する
  7. **写真の枠の一覧を作る。** SPEC.md に「写真の枠」の一覧を設け、枠ごとに、置く場所・PCとスマホでの縦横比・写したいもの・雰囲気・Unsplash で探すための英語の検索語を書く。写真は STEP 3 で Unsplash から選ぶ（顔がはっきり写ったもの・ロゴが写ったものは避ける）
- 「いい感じ」「程よく」などの感覚語は使わない。数値・色の値・要素名で書く

### STEP 3 実装
- SPEC.mdの数値をそのまま使う。「なんとなく良さそうな値」は入れない
- 修正は差分で行い、ファイルを全文書き直さない
- 確認はグループごと（共通部分→上半分→下半分など）にまとめて行い、細かく刻まない

### STEP 4 確認
```
node tools/ref-verify.mjs terms  templates/<ID>/terms.md  <成果物のフォルダ>
node tools/ref-verify.mjs photos templates/<ID>/photos.txt data/photo_ledger.csv
node tools/ref-verify.mjs table  data/diff_table.md
node tools/ref-verify.mjs ledger templates/<ID>/photos.txt data/photo_ledger.csv <ID>   # すべて問題なしのあとで
```
- どれも「問題なし」なら1行だけ出る。Claudeは結果の行だけを読み、成果物を目で読み直さない
- 目視で確かめるのは、完成したページのPC・スマホの全体像2枚だけ（`ref-capture.mjs` を自分の成果物に対して実行すれば同じ形で撮れる）

## 4. 燃費のルール

1. **見るより測る。** 数値で取れるものは画像で確認しない。画像は性格・空気感の判断にだけ使う
2. **画像は小さく、少なく。** 全体像は縮小済みのものを使う。スクロールしながら撮る方式はとらない（撮った画像が会話に残り、以後の毎回の読み直しに乗るため）
3. **長い出力を会話に入れない。** 実測の全データ（`measure-*.json`）は必要な項目を探すときだけ開く。ページの文字や構造を丸ごと読み込ませない
4. **判断の要らない作業はスクリプト。** 業種語の照合、写真の疎通、台帳の重複、差別化テーブルの空欄は `ref-verify.mjs` で行う
5. **会話を分ける。** STEPごとに新しい会話。前のSTEPの結果はファイルで渡し、会話の中で読み上げさせない
6. **確認はまとめる。** 1テンプレートあたりの確認は、STEP 2の終わり、STEP 3のグループごと、STEP 4の終わりを目安にする
7. **モデルを使い分ける。** STEP 1・4は軽いモデルで足りる。STEP 2（設計の判断）と、STEP 3のうち見た目の質を左右する部分に上位のモデルを使う
8. **一度分析したサイトは再分析しない。** `refs/<サイト>/` とSPEC.mdを残し、別テンプレートで同じサイトを使うときは再利用する

## 5. 品質を保つ仕組み

燃費のために省いた「目で見て気づく」部分は、スクリプトの警告で補う。`report.md` の冒頭に出る警告は次のとおり。

| 警告 | 意味 | 対処 |
|---|---|---|
| 読み込まれていない写真が○枚 | 写真が抜けた状態で実測・撮影した可能性 | もう一度実行。直らなければ6章 |
| 透明のままの要素が○個 | スクロールで現れる演出の取り残し | 同上 |
| 読み込めないスタイルシートが○件 | 見た目が崩れた状態で実測している可能性 | 6章 |
| フォントの読み込みが完了していない | 書体・文字幅の実測がずれる | もう一度実行 |
| ページが極端に短い／HTTP 400番台以上 | ブロック、同意画面、別ページ | 6章 |
| セクションを判定できなかった | 構成が特殊 | 全体像から目視で区切り、SPEC.mdに位置を書く |
| 全面写真のセクションが隣接 | 隣接衝突 | STEP 2で対策を決める（失敗ではなく設計事項） |
| 覆いを○件隠した | 同意画面などを隠して撮った | 隠したものが本文でないかだけ確認 |

- 「覆いを隠した」の括弧の中は、隠した要素の文字（先頭30字）を出す。**文字のない覆い**（全面の画像スプラッシュなど、同意画面以外の可能性があるもの）は、文字が出せないので代わりに **「文字なし ○×○ 写真あり／写真なし」**（覆いの大きさと、中に写真が入っているか）を出す。大きさが画面いっぱい（例：1440×900）で写真ありなら、本文（ファーストビューの写真など）を隠していないかを全体像で必ず確かめる

## 6. Chromeで分析する場合（例外）

次のときだけ、チャット＋Chromeの拡張機能で補う。**全体をChromeでやり直すのではなく、足りない部分だけ**を取る。

- 警告が消えない（自動操作を嫌うサイト、ログインや同意が必要なサイト）
- ホバーやクリックで変わる表現を確かめたい
- 動き（アニメーション）の速さや順番を確かめたい

Chromeで作業するときの節約術：
- 1サイトごとに新しい会話で始める
- 数値はページ上でJavaScriptを実行して取る（`ref-capture.mjs` の実測部分をそのまま貼って実行できる）
- スクリーンショットは必要な箇所だけ、ウィンドウを小さくしてから撮る
- 複数の操作は1回にまとめて実行する
- ページ全体の文字や構造を丸ごと読み込む操作は使わない
- 取れた結果は `refs/<サイト>/chrome-notes.md` に短く書き、STEP 2はClaude Codeに戻って行う

## 7. SPEC.md のひな形

```markdown
# SPEC：<テンプレートID>（参考：<URL>、取得日）

## 1. 対応表
| 固定セクション | 参考サイトの# | 背景 | レイアウト | 写真の比率 | 備考（対応なし→新規設計 等） |

## 2. 構造の数値（参考サイトの実測値をそのまま使う）
- コンテンツ幅 / 左右の余白（PC・スマホ）
- グリッド（列数・間隔、PC・スマホ）
- 余白のリズム（基本の刻み、セクションの上下余白）
- 文字の大きさの比率と行間（本文=1）
- 写真の比率・トリミング
- ヘッダーの高さ・固定の有無

## 3. 性格と、選び直した値
| 項目 | 参考サイトの性格（言葉） | 芦屋みっけで選んだ値 |
| 色 | 例：低彩度、背景は温かい白、文字は高コントラスト | 背景 #…、文字 #…、アクセント #… |
| フォント | 例：見出しは細めの明朝、本文はゴシック | 見出し …、本文 …（約30種から） |
| 角丸・影・ボタン・見出しの装飾 | | |

## 4. 隣接衝突の対策
## 5. 業種語の置換表（terms.md に同じ内容を置く）
| 参考サイトの語 | 置き換え後 |
## 6. 新規設計したセクション（派生元、確定値、禁止事項）
## 7. 写真の枠（STEP 3 で Unsplash から選ぶ。顔がはっきり写ったもの・ロゴが写ったものは避ける）
| 枠 | 置く場所（固定セクション） | 縦横比（PC） | 縦横比（スマホ） | 写したいもの | 雰囲気 | Unsplash 検索語（英語） |
## 8. 開いた切り抜きと理由
## 9. 使用写真（photos.txt に同じ内容を置く）
```

## 8. 過去に別プロジェクトで起きた失敗と、この手順での対策

| 失敗 | 対策 |
|---|---|
| 参考サイトの業種の言葉（英語タイトル）が残った | STEP 2で置換表、STEP 4で `terms` 照合 |
| 全面写真のセクションが連続し、縫い目なしにくっついた | 実測の警告 → STEP 2で対策 |
| テンプレート間で写真が大量に重複した | 写真台帳と `photos` 照合 |
| テンプレートごとにセクションの数・種類がバラバラになった | 固定セクション（2章） |
| テンプレート専用のデータ構造を作ってしまった | データの形は01・02で共通に定義済み。テンプレートは見た目だけ |
| 確認が多すぎて進まなかった | 確認は3か所にまとめる（4章6） |
| 押しても反応しないボタン、リンク先のない記事リンクが残った | 最初から実データ（①）に接続し、空なら非表示 |
| 実在の地名・人名がデモに残った | デモは架空の店（御菓子司 芦屋堂 など）。置換表に固有名も入れる |
| 分析に使用量を大量に消費した | 分析をClaude Code＋スクリプトへ移す（3章・4章） |
| 背景色だけの帯（例：News帯 #333）を取りこぼした（文字と写真だけ拾っていた） | COLLECT で色のついた面（帯・地・札・線）も測る。**要素の照合では見つからず、両側塗りの画素の比較（clone §2.3）で拾った**（2026-09-23） |

## 9. ファイルの置き場所

```
tools/ref-capture.mjs        撮影と実測
tools/ref-verify.mjs         機械でできる照合
refs/<サイト>/               実測結果（report.md、measure-*.json、overview-*.jpg、sec-*.jpg、chrome-notes.md）
templates/<ID>/SPEC.md       設計書
templates/<ID>/terms.md      業種語の置換表
templates/<ID>/photos.txt    使用写真（1行に「ラベル URL」）
data/photo_ledger.csv        写真台帳（photo_id,template,date）
data/diff_table.md           差別化テーブル（テンプレートを列に足していく）
```

- 準備：`npm i -D playwright` と `npx playwright install chromium`
- `refs/` の画像は参考サイトの複製なので、公開リポジトリに置かない（`.gitignore` 推奨。`report.md` とSPEC.mdだけ残せば再利用には足りる）

## 10. 動作確認の状況

- `ref-capture.mjs`：写真の遅延読み込み、スクロールで現れる演出、同意画面、全面写真の隣接を含む試験用ページと、既存の `feature_magazine_spread_original.html` で動作を確認済み。**実在の外部サイトでは未確認**（作成環境のネットワーク制限のため）。最初の実サイトでは、警告と全体像を見て取りこぼしがないかを確かめること
- `ref-verify.mjs`：4つの機能すべてで、問題あり・なしの両方を確認済み

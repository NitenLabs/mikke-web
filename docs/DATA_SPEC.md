- **v4（2026-10-09）**：お店の方の編集（③層の配置と編集。`record_layer3_editing_rules.md`、試験台23 まで）に合わせて、4章に 4.8〜4.11、5.2・6章・7章 Q1・8章を書き足し・書き直した。**schema（`site.schema.json` など）と書き出しの仕組みは、まだ v3 の形のまま**（移行は 4.11）。`DATA_SPEC_ch4_v3_additions.md` と `DATA_SPEC_v4_inventory.md` の中身は、すべてこの版に入れた
- **v4.1（2026-10-10）**：試験台24（24・24b・24c）で、下書きを 4.9 の形で保存して開き直す仕組みを作り、確かめた結果を 4.9〜4.11 に入れた。`seq`（連番）、足した部品の `size`・`style`・`section`、重なり順を `z` で持つこと、左右の入れ替えの持ち方、部品を指す所は全部の ID で書くこと、空の入れ物は書かないこと
- 判断の物差し：①納品後の工数ゼロ（問い合わせ・手直しが発生しない）、②オーナーが自分で直しても崩れない、③Studio級の見た目、④一人で運営できる（守るべき規則や外部の変化を増やさない）、⑤あとから変えられないものは今決め、あとから足せるものは今足さない

## 2. 全体に効く決まりごと

### 2.1 分からない値は「書かない」
- 値が分からない項目は**キーごと書かない**。`null` や空文字は使わない（検査で弾く）
- 書いていない項目は公開サイトで自動的に表示されない（01の5.2）
- 「ない」と「分からない」を区別したい項目は、書き方で区別する。例：支払い方法の `cards: []` は「カードは使えない」、`cards` がないのは「分からない」

### 2.2 ID
- すべての「もの」は、中身が変わっても変わらないIDを持つ。**一度使ったIDは、削除したあとも再利用しない**（履歴・連動・外部サービスとの突き合わせが壊れるため）
- 形：種類を表す接頭辞＋英小文字・数字4〜24文字（例：`itm_7k2m9q`）。4層を通して一意

| 接頭辞 | もの | 接頭辞 | もの |
|---|---|---|---|
| shp | お店 | pg | ページ |
| mnu | メニュー | sec | セクション |
| cat | 括り | el | 要素 |
| itm | 品 | cel | カードの中の要素 |
| plc | 載せ方 | ast | 素材（写真など） |
| lbl | ラベル | svc | 外部サービス |
| prc | 価格の選択肢 | acc | アクセス |
| exc | 営業時間の例外 | faq | よくある質問 |
| ppl | 人 | cfd | 自由項目 |

### 2.3 一覧は「IDをキーにした入れ物」＋並び順の数字
- 品・括り・要素などの一覧は、配列ではなく **IDをキーにした入れ物**で持ち、並びは `order` の数字で持つ（試作の `els` と同じ持ち方）
- 理由：値の場所を「`/catalog/items/itm_monaka/prices`」のようにIDで指せるので、並べ替えても確認待ちの記録や連動が壊れない
- `order` は小数も可。間に差し込むときは前後の中間の値を入れ、時々振り直す
- 例外として、価格の選択肢と1日の時間帯は短い配列で持つ（並びそのものに意味があり、数も少ないため）

### 2.4 値の形の要点
- **時刻**：`HH:MM`。深夜営業は日付をまたいで24時以降で書く（翌2時→`26:00`、上限`29:59`）。表示では「翌2:00」に変換する
- **価格**：数字（税込の円）＋種類（○円／○円〜／○円〜○円／時価／応相談／無料）。**税抜では持たない**（総額表示の義務のため）。店内と持ち帰りで価格が違う場合は、価格の選択肢の名前（「店内」「お持ち帰り」）か、テイクアウトのメニューだけの価格で表す
- **電話**：表示用（`0797-00-0000`）と発信用（`0797000000`）を両方持つ。入力時に自動で両方作る
- **SNS**：URLではなくユーザー名で持ち、URLは表示時に作る
- **色**：`#RRGGBB` か、テーマ色への参照 `theme:primary`。テーマ色で塗った箇所は、③でテーマ色を変えると一緒に変わる（PowerPointのテーマの色と同じ）
- **写真**：①②③は④のIDで参照するだけ。実物は④にしかない

### 2.5 多言語化の余地
- 今は日本語だけ。①の `translations` に「訳す値の場所 → 言語ごとの訳」を持てる場所だけ決めておいた（01の5.6「余地だけ残す」）。形を変えずに後から足せる

### 2.6 データの形を変えるとき
- 各層の先頭に `schemaVersion`。形を変えたら番号を上げ、古い版のデータを引き上げる変換スクリプトを必ず添える
- 項目を**足す**だけなら番号は上げなくてよい（書いていない＝非表示なので、既存のお店は何も壊れない。01の5.3）

## 3. ① お店の情報（shop.schema.json）

### 3.1 中身の一覧
| 区分 | 主な項目 | 01・02との対応 |
|---|---|---|
| basic | 店名、読み方、業種のひな形、表示用の業種名、ひとこと紹介 | 01の5.2 基本 |
| location | 郵便番号〜建物名、緯度経度、番地を隠す、最寄り駅からの行き方、駐車場 | 01の5.2 場所 |
| hours | 曜日ごとの表、祝日の扱い、定休の規則、決まった期間の例外、補足 | 01の5.2 時間、02の1.3 |
| contact | 電話、FAX、メール、SNS | 01の5.2 連絡 |
| reservation | 予約の要否、方法、補足 | 01の5.2 連絡 |
| externalServices | 通販・テイクアウト・デリバリー・予約の外部サービス | 02の5B.2 |
| payment / facilities | 支払い方法、席数・禁煙・子ども連れ・車椅子など | 01の5.2 その他 |
| genreInfo | 業種ならではの情報（取り置き、指名料、診療科目、保険、体験レッスン、対応エリアなど） | 01の5.2 の表の右列 |
| story | 創業年、店主の名前、短い問いへの答え | 02の1.8 |
| faq / people / customFields | よくある質問、人（スタッフ・医師・講師）、自由項目 | 01の5.2 |
| catalog | メニュー → 括り → 品、載せ方、ラベル | 02の3章 |
| review | 取り込んだ値の確認状態 | 02の1.4 |
| translations | 多言語化の余地 | 01の5.6 |

### 3.2 営業時間
- **曜日ごとの表**：各曜日は「営業／休み／予約のみ」＋時間帯（1日に複数可、名前とラストオーダーを任意で持つ）。曜日のキーがなければ「分からない」
- **祝日の扱い**：曜日どおり／休み／祝日だけの時間
- **定休の規則**：曜日の表では表せないもの。「第3火曜」「最終水曜」「不定休」。曜日の表より優先する。不定休があるお店では「本日営業中」のような断定表示をしない
- **決まった期間の例外**：年末年始・お盆など、あらかじめ分かっている期間（毎年くり返し／その年だけ）。**当日の臨時休業の知らせには使わない**（お知らせ機能は作らない方針）。その年だけの期間は過ぎたら自動で表示から消え、1年後に自動で削除する（7章Q2）
- **補足**：形に収まらないことは自由記入
- 同じ形（時間帯）を、甘味処やランチのような「メニューの提供時間」、教室の「開講時間」にも使う

### 3.3 メニューの3段（02の3章をそのまま形にしたもの）
```
catalog
  menus       メニュー（名前、説明、提供時間、メニュー全体の注文先）
  categories  括り（どのメニューの括りか、名前、注記、写真）
  labels      ラベル（名前、仕組みが意味を知っているものは system）
  items       品（名前、説明、写真、ラベル、基本の価格、販売状況、時期、注文先…）
  placements  載せ方（どの品を、どのメニューの、どの括りに、何番目に、そのメニューだけの価格）
```
- 1段目を使わないお店（物販・美容など）も、**名前のないメニューを1つ持つ**。画面ではメニューの段を見せない。これで業種ごとに形を変えずに済む
- **1つのメニューの中では、品の置き場所（括り）は1つだけ**。同じ品を別のメニューに載せるのは自由（わらび餅：店頭450円、甘味処はお茶付き650円）
- **メニューだけの価格は、品の価格を丸ごと置き換える**。選択肢の数や名前もメニューごとに変えられる（例：店頭は「1個／5個入り」、甘味処は「お茶付き」だけ）。部分的な上書きにしなかったのは、画面で「このメニューの価格」をそのまま見せられて分かりやすいため
- **ラベル**のうち、おすすめ（＝代表の品）・新商品・辛い・ベジタリアン・テイクアウト可・数量限定は仕組みが意味を知っているもの（`system`）で、消せない（名前は変えられる）。ほかはお店が自由に作れる
- **季節限定はラベルにしない**。品の「販売時期（月）」を書けば、その月だけ自動で表示され、「季節限定」の印も自動で付く。ラベルと時期の二重管理でずれる事故を防ぐため
- 品の業種別の項目：所要時間（美容・治療院）、開講の曜日・時間と対象（教室）、保険／自費（医療・治療院）。アレルギーは持たない（7章Q4）
- **人（スタッフ・医師・講師）はメニューとは別の一覧**にした。売り物ではなく、価格も括りも持たないため

### 3.4 品を表示するかどうか（表示の仕組みの決まり）
品は、次のすべてを満たすときだけ公開サイトに出る。
1. 販売状況が「販売中」
2. 販売時期（月）があれば、今月がその中に入っている
3. 販売開始日があれば、その日を過ぎている。終わりの日があれば、その日を過ぎていない
4. どこかのメニューに載っている

2と3は日付で変わるので、**公開中のサイトを毎日0時（日本時間）に自動で書き出し直す**。オーナーが「公開」を押さなくても季節の品が出入りするのは、02の5.2で決めた「自動で表示・非表示」の道具どおりの動き。
- 表示する価格は「載せ方の価格があればそれ、なければ品の価格」。`hidePrice` の品と、価格が空の品は価格を出さない
- 品が1つも出ない括りは、見出しごと出さない

### 3.5 取り込んだ値の確認（review）
- 事前取り込み（02の1.4）で入れた値は、本文にはふつうに値として入れ、**確認状態を別の欄（review）に「値の場所 → 状態」で持つ**。値を包む形にしなかったのは、表示の仕組みが確認状態を一切気にせずに済むため
- 状態は3つ：確認待ち／出どころで食い違い（オーナーへの質問）／読み取れなかった
- 食い違いのときは、本文には優先度の高い出どころの値（芦屋みっけの裏取り＞お店自身のサイト＞Googleマップ）を入れておき、ほかの候補は `sources` に並べる
- オーナーが「合っています」または「直す」を押したら、reviewの行を消し、変更の記録に残す（ここで一次情報になる）
- **最初の公開の条件**：食い違いと読み取れなかった値が0件であること。確認待ちは残っていても公開できる（制作側が判断）。検査はこの件数を警告で出す

## 4. ② サイトの組み立て（site.schema.json）

### 4.1 全体の形

> **v4 注記**：4.1〜4.7 は、制作側が組むサイトの形（今の書き出しの仕組みが使っている形）。お店の方が編集するサイトは「テンプレート＋お店の下書き」で表す（4.8〜4.11）。4.4〜4.7 の中身の決まり（文字のかたまり・連動・リンク・繰り返す部品・材料）は、そちらでもそのまま使う

```
canvas     位置の基準（PCの中身の幅、スマホで配置を作った幅）
pages      ページ（種類、アドレス、メニューでの表示名・順番、公開・非公開、セクションの並び、検索・共有用の情報）
regions    ヘッダー・フッター（全ページ共通のセクション）
sections   セクション（背景の色・写真、高さ、ページ内リンクの行き先）
elements   要素（材料）
```
- 試作 `editor_prototype.html` の `{sections, els}` を、複数ページ・共通部分・連動・繰り返す部品まで広げた形。試作の値の持ち方（位置は幅に対する％、縦はpx、端末ごとの `layout`、`locked`、`hidden`）はそのまま引き継いだ
- ヘッダー・フッターも普通のセクションとして持ち、`regions` から指す。ここを編集すると全ページに反映される
- ページの「見つからないとき」「プライバシーポリシー」も普通のページとして持つ（中身は自動）
- **背景の交互（`sections[].background.alternate`）**：`true` にすると、**表示されているセクションの順番**で `theme:background` と `theme:surface` を交互に使う（非表示のセクションがあってもずれない）。`color` を明示すればそちらが優先。隣り合う全面写真のセクションの縫い目を、色の切り替えで断つのに使う
- **ヘッダーを重ねる（`regions.headerOverlay`）**：重ねるページのIDの一覧（`pages`）と、重ねたときの文字の色（`textColor`）を持つ。指定したページでは、ヘッダーを最初のセクションの上に**透明で**置く（ファーストビューの暗い写真に重ねる）。IDの実在は検査で確認。**スクロールすると通常のヘッダーの見た目（背景 `theme:background`・文字 `theme:text`・線 `theme:line`）に戻る**（重ねるのはページ先頭にいる間だけ）
- **ページ移動のメニュー（ナビ）**：ナビは「ページ（`showInNav`）」と「`nav` を持つセクション（`sections[].nav`＝ナビでの名前 `label` と順番 `order`）」から自動で作る。ページの項目はそのページへ、セクションの項目はそのセクションの `anchor` へのページ内リンクになる。並びはページの `navOrder` とセクションの `nav.order` をまとめて昇順。**セクションが空で表示されなくなったら、そのセクションのナビ項目も自動で消える**（1ページの中に長く積んだ構成を、ナビの行き先で表せる）。`nav` を持つセクションには `anchor` が必要（検査で確認）

### 4.2 位置と大きさ、画面の幅の違い

> **v4 注記**：この節の「位置は幅に対する％・h は必須」は、今の書き出しの仕組みが使っている形。お店の方が編集するサイトでは、テンプレートの仕組み（4.8）と手直し（4.9）に置き換わる。**画面の幅の違いの扱い（スマホは 390 の配置を比例で拡大縮小、PC は中身の幅を真ん中に置き狭い窓では縮小）は、置き換わった後もそのまま使う**（7章 Q6）

- 端末ごとに別：x（％）、y（px）、幅w（％）、配置したときの高さh（px）、写真の枠の形、文字の大きさ、線の太さ、**文字の向き（縦書き `writingMode`）**
- **h は写真以外すべて必須**。文字の h は、編集画面が配置を確定したときの実際の高さを書き込む（4.3の規則の基準になる）
- **縦書きは layout（端末別）に持つ**：縦書きは「その端末でどう置くか」なので、位置・大きさと同じ `layout.pc`／`layout.sp` の中に `writingMode` を持つ（PC は vertical・スマホは horizontal のように端末別に変えられる）。`vertical` の端末でも h は必須で、箱は大きさ（w・h）を固定して伸びない（4.4）
- **使う配置**：画面幅768px未満はスマホの配置、768px以上はPCの配置（タブレットは縦ならスマホ寄り、横ならPC寄りになる。3つ目の配置は作らない）
- **スマホ**：配置を作った幅（芦屋堂は390px）を基準に、**位置・大きさ・文字の大きさをまとめて比例で拡大縮小**する。360pxの機種なら全体が約92%になる。倍率は0.82〜1.15に収め、それより広い画面（大きめのタブレットの縦など）は中央に置いて左右に余白を取る（7章Q6）
- **PC**：中身を中央の決まった幅（芦屋堂は1100px）に収め、`fullBleed` の要素と背景だけ画面いっぱいに広げる（01の3.5）。画面が中身の幅より狭いときは全体を比例で縮小する（下限0.7。それより狭ければスマホの配置）

### 4.3 伸び縮みの規則（重ならず、穴も開かない）

> **v4 注記**：狙い（重ならず、穴も開かない）は変わらない。手段は、テンプレートの縦積み・付いていく先・間隔の決まり（4.8）に置き換わる。置き換わった後は `reflow.mjs` と「h は必須」を外す。規則7（飾りしか残らないセクションは出さない）と、段落ごと消える決まり（4.4）は、置き換わった後も使う

自由配置では、文章が長くなる・品が増える・項目を空にする、のたびに要素どうしが重なったり、穴が開いたりする。これはオーナーが自分では気づけず、気づいても直し方が分からない崩れで、工数ゼロと正面からぶつかる。そこで、**データの位置は一切書き換えず、表示するときだけ**次の規則でずらす（7章Q1）。

1. 下端が別の要素の上端より上にあり、横の範囲が重なっているとき、その要素は「上にある」
2. 伸びた量：表示中の要素は「実際の高さ − h」（0未満は0）。箱を中身より大きく取ってあれば、その中で伸びる分は下を動かさない
3. 空欄で消えた要素：自分の高さと、すぐ下の要素までの間隔をまとめて詰める
4. 各要素は、すぐ上にある要素たちの「ずれ＋伸びた量」の最大値だけずれる。横に並んだ2列は互いに影響しない
5. 写真の上に重ねた見出しのように、別の要素の縦の範囲に収まっている要素は、はみ出した分だけ下を押す
6. セクションの高さも同じ規則で伸び縮みする
7. **飾り（図形・背景写真・背景色だけの要素）以外の要素がすべて消えたセクションは、セクションごと表示しない**（飾りしか残らないセクションを出さない）

- 参照実装は `tools/reflow.mjs`、動作は `tools/reflow.test.mjs`（文章が伸びる、2列、全幅、空欄で消える、余白を取った箱、写真の上の見出し、品が増える、飾り以外が全部消えたセクション、など13の場面）
- **規則7（セクションごとの非表示）も `tools/reflow.mjs` が判定する**（要素に `decorative:true` を付け、戻り値の `hidden` で返す）。表示の仕組みは `hidden` が真のセクションを描かない
- 編集画面でも同じ規則で表示する。オーナーから見ると「文章を足したら下が自然にずれた」になり、配置は勝手に書き換わらない（01の2.2「他の要素の大きさが勝手に変わらない」と両立する）
- 制作側の作法：情報の欄（営業時間・住所・電話など）は、項目ごとに別の箱にせず、**1つの文字の箱の段落として並べる**のを基本にする。段落単位で消えるので、箱の中で自然に詰まる

### 4.4 文字：3種類の「かたまり」
文字は「段落 → かたまり」の形で持つ。かたまりは3種類。

| かたまり | 例 | 動き |
|---|---|---|
| 自由な文字 | 「季節を、ひと口に。」「営業時間　」 | そのまま表示 |
| 連動している文字 | ①の `/hours` を「9:00〜18:00（水曜定休）」の書き方で | ①が変われば変わる。空なら表示しない |
| 連動を外した文字 | 「この場所だけ別の文章にする」をしたもの | 外した時点の元の値を控え、元の値が変わったら「古い内容のままかもしれません」と知らせる。あとから連動に戻せる |

- **連動は文字の箱単位ではなく、かたまり単位**にした。「営業時間　」（自由な文字）＋営業時間（連動）を1つの箱の中で並べられる。試作の店舗情報の欄がまさにこの形
- **空の扱い**：連動している文字を含む段落は、その段落の連動先がすべて空なら段落ごと消える（「営業時間　」のような見出し語も一緒に消える）。全段落が消えた箱は箱ごと消える。自由な文字だけの段落は消えない
- **縦書き**：文字の向きは**箱の設定（style）ではなく layout（端末別）に持つ**（`layout.pc.writingMode` 等、4.2／7章Q7）。縦書きの箱は大きさ（w・h）を固定し、中身が入りきらなければ編集画面で知らせる（伸びない）。同じ文字を PC は縦書き・スマホは横書き、と1つの要素で切り替えられる（2つの要素を持って出し分けると、片方だけ直す事故が起きる）
- **改行の位置は表示の仕組みが決める（fix04 §1）**：文章の改行は、書き出しのときに仕組みが決める。①文節の途中では折らない（BudouX で文節に分け、文節の間だけで改行する）。②段落の最後の行が短くなりすぎない（最後の行の文字が4未満なら、末尾の文節をまとめて次の行へ送る）。③見出しは行の長さをそろえる。**データに改行の調整（空白・改行文字・`<br>`）を書かない。** データに書く改行（例：ファーストビューの「季節を映す、／ひと口の和菓子」の「／」）は、**段落の区切り**としてだけ使い、その区切りで分かれた各段落の中で上の規則が効く。`site.lineBreakRules: false` で規則を切れる（第2部 clone の検証用。既定 true）。`noWrap`・縦書きの要素はこの規則の対象外。
- **折り返さない（`style.noWrap`、真偽）**：`true` にすると箱の文字を折り返さない（`white-space:nowrap`）。短い札（営業案内）・ピルのボタン・ナビ・FAQ の「Q.」など、**必ず1行で見せたい文字**に使う。**実測もこの設定で1行として測る**ので、箱の幅が中身ぎりぎりのときに描画エンジン（chromium/webkit/firefox）や端末幅で折り返しが変わって高さがぶれる事故を防ぐ（スマホは390の配置を比例縮小するだけなので、360でも390と同じ1行に保たれる）。縦書きの箱は自前で1行固定なので指定しない
- **項目名の列（`labelColumn`、em）**：文字の箱の設定に付けると、各段落の**先頭の自由な文字**をその幅の列に置き、残りを右に流す。営業時間・住所などの定義リストを、**項目名と値を別の箱にせず1つの箱**で表せる（4.3の作法どおり）。段落ごと消える規則はそのまま（連動先がすべて空の段落は、先頭の項目名ごと消える）
- 複雑な値の書き方（`format`）：曜日ごとの表、短い一行、定休日、住所（全部・町名まで）、アクセス、電話、支払い方法、価格（1つ・全部・税込表記 `priceAllTax`＝「1個 220円／5個入り 1,200円（税込）」）、創業からの年数、席数、**フラグ（true/false の項目）**
- **フラグ（`format="flag"`）**：`true` なら段落の**自由な文字だけ**を出し、`false`・空なら**段落ごと消す**。のし・包装・取り置きのような「やっている／やっていない」の項目に使う。理由：**「できません」とは書かない**（やっていないことをわざわざ載せると印象が悪く、情報も薄く見える）。連動先が空の段落が消えるのと同じ挙動で、値が偽のときも段落ごと消える
- **価格の数字**：価格は `font:accent`（欧文の飾りフォント）で出し、数字は **`lining-nums`（大文字と同じ高さにそろえる）・`tabular-nums`（等幅の数字）** を効かせる（桁がそろい、金額として読みやすくなる）。**STEP 3 で、配信するフォントがこの数字機能に対応しているか確かめる。非対応なら価格は本文の書体（`font:body`）に統一する**（EB Garamond などのオールドスタイル数字は高さ・幅がそろわず、価格の桁が乱れるため）
- 一部だけの装飾（フォント、周りの何倍の大きさ、色、太字・斜体・下線、リンク）は、かたまりごとに持つ
- 文字の箱全体の設定は、書いていないものは③の役割ごとの標準に従う

### 4.5 リンク
- 種類：ウェブページ、電話、メール、Instagram、サイト内のページ、ページ内の場所、外部サービス
- **お店の情報を使うリンク**を足した：お店の電話、お店のメール、お店のInstagram、お店のLINE、お店の地図、品の注文先。「電話する」ボタンが①の電話番号を見るので、番号が変わっても直さずに済む
- サイト内のページはアドレスではなくページのIDで指す（アドレスが変わってもリンクが切れない）

### 4.6 繰り返す部品
- **何を並べるか**：メニューの品（メニュー、括りの絞り込み、ラベルの絞り込み、直接選ぶ、件数、括りごとに見出しを挟む）／人／よくある質問／写真の並び
  - 例：トップの「おすすめ」＝店頭販売のうちおすすめのラベルの品を3件。メニューページ＝店頭販売の全品を括りごとに
- **どう並べるか**：格子／一覧／スライドショー／**開閉式（accordion）**、横の列数（端末別）、間隔、**写真のない品の出し方**（同じカード／文字だけの詰めたカード／出さない）。開閉式は見出しを押すと中身が開く見せ方で、**よくある質問の一覧（kind=faq）でだけ使える**（検査で確認）
- **カードの設計**：カード1枚の中に文字・写真・図形を置き、中身は「その1件」の項目と連動させる。連動で使える品の項目には、品そのものの項目に加えて **括り**（`/category/name`）と**メニュー**（`/menu/name`）がある。`/prices` はそのメニューで表示する価格（載せ方の価格があればそちら）になる
- 括りごとに並べるときは、括りの見出しの設計も持つ
- スライドショーは独立した材料にせず、繰り返す部品の見せ方の1つ（01の5.5）
- **編集画面で品・表の行を足す・複製する・消すとき**（v4・**未決**）：見立ては、並びの種類で意味を変える。**全部を並べる所**（メニュー・括りの全品）では①を直す（足せば①のメニューに品が増え、名前・値段を書き換えれば①が変わる）。**絞り込んで並べる所**（ラベル・件数・直接選ぶ）では①の品は増減させず、「この並びに入れる・外す」＝ラベルや直接選ぶの中身を変える。①とつないだ試験台で両方の並びを触ってから決める

### 4.7 そのほかの材料
- **写真**：素材のID（または、カードの中で品の写真と連動）、見せる範囲、角の丸み、補正、暗くする、説明文、リンク（v4：お店の方の編集で触れるのは、差し替え・外す・見せる範囲・明るさ・リンク。形は 4.9。角の丸みはお店の方には出さない）
- **図形**：四角・丸・線、色、角の丸み、透明度、リンク（図形＋文字＋リンクでボタン）
- **埋め込み**：地図・Instagram・動画・注文ボタン・予約など。中身は制作側だけが触る。地図は①の位置から自動
- **フォーム**：お問い合わせ／予約のご希望、項目（ひな形から選ぶ）、送信先、自動返信。オンならプライバシーポリシーのページが必須（検査で確認）
- **ページ移動のメニュー**：中身はページの設定から自動。見た目だけ持つ
- **動き**：動きの種類は制作側、オン・オフはオーナー

### 4.8 テンプレートの組み方（v4）

お店の方が編集するサイトは、**テンプレート（版つき）＋お店の下書き**で表す。テンプレートは制作側が作り、お店の方は触らない。お店のデータは座標を持たない。

- **塊で組む**：テンプレートの部品は塊（縦積み・横並び・格子・重ね）で組む。座標はブラウザが計算する。中身が増えれば押し出し、減れば詰める
- **部品 ID**：テンプレートの部品は、テンプレートの中で一意の ID を持つ（例：`F_h0`、`card_name_c_warabi`）。手直し・中身はすべてこの ID で持つ
- **端末ごとの組み方**：PC とスマホで別の組み方を持つ（並び・大きさ・文字の大きさ・縦書き `writingMode` など）。中身は両端末で共通
- **間隔**：縦積みの隣どうしの間隔は、テンプレートが持つ。お店の方が並びを変えたときの間隔は、テンプレートの間隔から計算する（4.10）
- **重なり順の初め**：テンプレートが描く順（後から描くものほど前）
- **セクションの型**：テンプレートは、足せるセクションの型（`feature`・`items` など）と、その見本の文章を持つ。**動かせない・消せないセクション**（一番上の大きな写真、一番下のお問い合わせ・足元）もテンプレートの決まりとして持つ
- **テンプレートの版**：テンプレートを直したら版を上げる。下書きは、作ったときのテンプレートの名前と版を持つ。版を上げるときに、消した印（4.9）の部品は生き返らせない

### 4.9 お店の下書きの形（v4）

```
draft
  template      テンプレートの名前と版
  sections      セクションの並び [{id, type, from?}]
  content       部品 ID → 中身（文字・写真・部品まるごとのリンク）
  added         足した部品
  removed       消した部品・セクションの印
  adjust        手直し：pc / sp → 部品 ID → 性質
  textStyle     箱まるごとの文字の見た目：部品 ID → {…}
  seq           次に使う連番のための、使った最大の番号 {sec, add}（v4.1）
```

- 下書きは**今の形だけ**を持つ。操作の記録（戻すの記録）は持たない（4.10・6章）
- **中身**（sections・content・added・removed）は両端末で共通。「このページを元に戻す」で残る
- **デザイン**（adjust・textStyle）は「このページを元に戻す」で戻る
- 値の単位：位置・大きさは、その端末の設計の幅での px（スマホは 390、PC はテンプレートの中身の幅）
- 何もしていない所は書かない（2.1 と同じ）。テンプレートと同じ値も書かない。**中身が空の入れ物も書かない**（`adjust.sp: {}` のような空のものは書かない）。何もしていない下書きは `{template, sections}` だけになる（v4.1）
- `sections` は、テンプレートのままの並びでも書く（下書きの骨組み）
- **連番（`seq`）**（v4.1）：`sec` はセクション ID（`sec1`…）、`add` は足した部品・複製した品の ID（`add_*`・`addp_*`・`c_dup*`）に使った最大の番号。消しても減らさない（2.2）。0 なら書かない。開くときは、`seq` と下書きの中にある ID の番号の大きい方から続ける（下書きの ID を使い回さないための守り）
- 品・表の行（4.6）の持ち方は、まだ決めていない（4.11 の④）。試験台は、テンプレートと違うときだけ `_pg.rows[セクションID] = {cards?, table?}` に器ごと持っている（v4.1）

#### 4.9.1 手直し（adjust。端末ごと）

| 性質 | 形 | 編集の決まり（記録） |
|---|---|---|
| 位置・同じ塊の中 | `move: {dx, dy}`：テンプレートの位置からの総ずれ。2回以上動かしたら積み重ねる | 2.3 |
| 位置・塊の外 | `place: {after, gap, x}`：何の部品の下に（`after`＝部品 ID）・どれだけ空けて・横の位置 | 2.4・4.1〜4.3 |
| 並び順 | 縦積みの塊の ID → 子の部品 ID の並び | 2.6・2.7 |
| 左右の入れ替え | セクション ID → `swap: {塊の名前: true}`（1つのセクションに入れ替えられる塊が複数あり得るため、セクションごとにまとめる。v4.1） | 2.8 |
| 大きさ | 文字 `{w, padB}`（`padB` は文字の下に足した空き）／写真 `{w, h}`／区切り線・ボタン・表・品の並び `{w}` | 6章 |
| 重なり順 | 部品 ID → `z`（数字。大きいほど前）。同じ数字を作らない。テンプレートの描く順のままの部品は書かない（v4.1：並びではなく部品ごとの数字で持つ） | 5.4・5.5 |
| 品の並びの列 | 品の並びの ID → `cols`（PC 2〜4、スマホ 1〜2） | 6.7 |
| 写真の見せる範囲 | `view: {x, y, zoom}`。`x`・`y` は枠の真ん中に来る画像の点の割合（0〜1）、`zoom` は 1〜4。差し替えたら消す | 9.5〜9.7 |

- 品・表の行の中の部品は、1行の作りの部品 ID（全件で共通）に付ける。1件だけの位置は持たない（2.10）
- どれも、触った端末の `adjust[端末][ID]` の下に書く。触っていない端末には書かない（列・見せる範囲・左右の入れ替えも端末ごと。v4.1）
- 形の例：`adjust.pc.F_h0 = {move: {dx: -8, dy: 8}, size: {w: 420}}`、`adjust.pc.I_cards = {cols: 3}`、`adjust.sp.F_p0 = {view: {x: 0.4, y: 0.6, zoom: 2}}`、`adjust.pc.feature = {swap: {…: true}}`、縦積みの並び順は塊の ID に `order: [部品ID…]`

#### 4.9.2 箱まるごとの文字の見た目（textStyle）

`{weight?, color?, font?, size?: {pc?, sp?}}`

- `weight`（700／400）・`color`・`font` は両端末で共通。`size` だけ端末ごと（px、8〜120）
- 色・書体は、テンプレートのものなら名前（`text`・`textMuted`、`heading` など）、それ以外の色は `#rrggbb`
- 「文字の見た目を元に戻す」で、これと文の一部の見た目（4.9.3）の両方を消す（記録 8.12）

#### 4.9.3 中身（content・sections・added・removed。両端末で共通）

| もの | 形 | 編集の決まり（記録） |
|---|---|---|
| 文字 | 切れ目の並び `[{text, bold?, color?, scale?, font?, link?}]`。隣どうしで見た目が同じならまとめる。見た目のない文字は文字列だけでよい。`scale` は箱の大きさに対する倍率。4.4 の「一部だけの装飾は、かたまりごとに持つ」を、この形で持つ | 8.8〜8.11・8.13 |
| リンク | `link`：お店の情報の種類（電話・地図・Instagram・LINE・メール。値ではなく種類で持つ）／サイトのページの ID・ページの中の場所／よそのアドレス。文の一部（上の `link`）にも、写真・ボタンの部品まるごとにも付けられる。種類は 4.5 に合わせる | 8.14〜8.16 |
| 写真 | `{asset?, cleared?, bright?}`。`asset` は④の ID（キーがない＝まだない写真。編集では薄い枠、公開では詰める）。`cleared: true`＝お店の方が「写真を外す」をした。`bright` は −40〜+40（%）、写真を変えたら書かない | 9.1〜9.4・9.11 |
| セクションの並び | `[{id, type, from?}]`。`from` は複製なら元のセクション ID、足したなら `'@new'`、テンプレートにあったものは書かない。背景の色は持たない（並び順から決まる） | 12章 |
| 足した部品 | `{id, kind, placedOn, anchor, size, from?, style?, section?}`。`kind` は写真・文字など、`placedOn` は足した端末（`pc`／`sp`）、`anchor` は足したときの付いていく先。`size` は**足したときの両端末の大きさ** `{pc: {w, h?}, sp: {w, h?}}`（コピー元を後で直したり消したりしても、足した部品の大きさが変わらないように持つ。v4.1）。`from` はコピー元（分かるときだけ）、`style` は文字の種類（本文の既定と違うときだけ。コピー元によって変わるため。v4.1）、`section` は `anchor` が足した部品を指していてセクションをたどれないときだけ（v4.1）。中身（文字・写真）は `content[id]`。置いた端末で置き直した位置は `adjust[placedOn][id].place`、後から変えた大きさは `adjust[端末][id].size`。**もう一方の端末の位置は書かない**（4.10）。「元の位置に戻す」をした足した部品は、`place` を書かないことで自動の位置を表す | 9.9・9.10・9.12・11章 |
| 消した印 | 消した部品・セクションの ID の並び | 11.4・12.7 |

**ID の決まり**
- テンプレートにあったセクションの部品は、テンプレートの部品 ID のまま
- 複製・足したセクションの部品は `<セクションID>__<テンプレートの部品ID>`（例：`sec3__F_h0`）
- セクション ID（`sec1`、`sec2`…）と足した部品の ID は増える一方で、一度使ったら使い回さない（2.2 と同じ）。そのための番号は `seq` に持つ（4.9）
- **部品を指す所も全部の ID で書く**（v4.1）：`place.after`・`added[].anchor`・並び順（`order`）の中の部品 ID など。複製したセクションの中の部品を素の ID（`F_p0`）で書くと、元のセクションの部品と区別できないため。`@section` などの印と、足した部品の ID（`add_*`）はそのまま

#### 4.9.4 戻す範囲（データで見たとき）

### 4.11 今の schema・書き出しの仕組みとの関係（v4）

- 4.8〜4.10 は、**まだ schema にも書き出しの仕組みにも入っていない**。今の `site.schema.json`・`reflow.mjs`・書き出しは、4.1〜4.7 の形（位置は％・h は必須）のまま。試験台（`refs/compare/layout/playground24_single.html`）は、4.9 の形で下書きを保存して開き直す（試験台24・v4.1）。品・表の行だけは `_pg.rows` に仮置き（4.9）。下書きの見本：`refs/compare/layout/playground24/draft_sample.json`
- 移すときは、形が変わるので `schemaVersion` を上げ、古い形を引き上げる変換を添える（2.6）
- 移す前に試験台で確かめること：①スマホの 360・430 の幅で、390 と同じ形になるか ②その幅で、書き換え・文字の選び方・日本語の変換がずれないか（縮めた中での書き換えは iPhone の Safari で崩れやすい。崩れたら縮め方を変える：見た目だけ縮める／大きさの数字を倍率で掛けて組む）③360 の幅で文字が読める大きさか ④品の並びを①とつないで、全部を並べる所・絞り込んで並べる所の両方で品を足す・消す（4.6）
- **①〜③ の Chromium での結果**（試験台25・v4.1）：倍率は `clamp(画面の幅 / 390, 0.82, 1.15)`、1.15 を超える幅は真ん中に置く。PC の窓で「スマホ」に切り替えて直すときは 1 倍のまま。320〜600 の7つの幅で、位置・大きさは 390 と 0.5 以内、文字の折り返しは全部の箱で 390 と同じ。一番小さい文字（設計 14px）は、360 で約 12.9px、320 で約 11.5px。縮めた中での文字の当たり・選び方・変換・ドラッグ・つまみ・吸い付きはずれない。つまみ・ボタン・吸い付きなどの指の大きさの数字は、倍率によらず画面の上で同じ（記録 14.2〜14.9）
- 縮め方は2つ用意してある：**A（見た目だけ縮める＝`transform`。既定）**と **B（CSS の `zoom`。`?scale=zoom`）**。Chromium では A と B は同じに動く。残りは iPhone の Safari での確認（記録 14.10）。A で崩れたら B、B でも崩れたら「大きさの数字を倍率で掛けて組む」

## 5. ③ 見た目の設定・④ 素材置き場

### 5.1 ③ 見た目の設定（theme.schema.json）
- **テーマ色**：必須の6色（背景、面、文字、薄い文字、メイン、差し色）＋追加で最大10色まで。色には「墨」「生成り」のような名前を付けられる
- **フォント**：見出し用・本文用・飾り用（任意）。要素側は `font:heading` のようにテーマのフォントを参照できる
- **文字の役割ごとの標準**：ページの見出し、見出し、小見出し、本文、注記。新しく足した文字の初期値になり、検索エンジン・読み上げ向けの見出しの階層もここから決まる
- ③は②と同じ下書き（サイトの組み立ての下書き）に入る

### 5.2 ④ 素材置き場（assets.schema.json）
- 写真ごとに：種類（写真／ロゴ／制作用の資料）、ファイルの情報、誰がいつ上げたか、出どころ（オーナー、Instagram、お店のサイト、旧サイト、制作側）、**使う権利**、素材集めの枠（外観・看板商品など）、標準の説明文、ゴミ箱に入れた日時
- **公開サイトに使えない写真**を検査で止める：権利が未確認のもの（旧サイトの写真など）、制作用の資料（お品書きの写真など）、ゴミ箱のもの、位置情報を消していないもの
- 表示用の縮小版は公開時に自動で作るので、台帳には持たない
- **元の写真も残す**（v4）：お店の方が上げた写真は、縮める前の元の写真も置き場に持つ（位置情報は消し、向きは直す）。編集の画面は長い辺 2400px の版を使い、公開するときは元の写真から、見せる範囲（1〜4倍）に足りる細かさで表示用を作る。受け付ける大きさの上限は保存の仕組みのときに決める
- **版が指している写真は消さない**（v4）：下書き・版は写真を ID で指すだけで、ファイルは置き場に1つ。ゴミ箱に入れても、公開中の版・公開した版の履歴・戻す前の下書きのどれかが指している間は本当には消さない。どれにも指されなくなったら消してよい
- ④は下書きの対象外。上げた時点で置き場に入り、どこかで使われて公開されるまでは外から見えない

#### 素材サイトの写真（stock）— サンプルの店だけ実物の枠に使える
- 出どころ（origin.kind）に **`stock`**（Unsplash などの素材サイト）を用意した。`stock` の写真には出どころに **`provider`（"unsplash"）と `pageUrl`（写真の紹介ページのURL）が必須**、`credit`（撮影者名）は任意（クレジット表示に使う）。`stock` の写真は使う権利が **必ず利用許諾（rights.basis = licensed）** になる
- **実在の店では、`stock` を「実物の枠」に使えない**（検査でエラーにする）。実物の枠とは、素材集めの枠 `slot` が **外観・看板商品・店内・作業風景・スタッフ・品（exterior・signature・interior・work・staff・product）** のもの、および **品の写真・人の写真・括りの写真**。**飾りの写真（背景の質感など＝`slot` が other や、セクションの背景）は実在の店でも使ってよい**
- **架空のサンプルの店（① の最上位に `isSample: true`）だけ**、`stock` を実物の枠に使える。芦屋堂はこれにあたる（検証用のサイトを、実在の写真を集める前に組み立てられるようにするため）
- **理由**：素材サイトの写真は「よそのお店・よその品」であって、そのお店の実物ではない。実在の店のファーストビューや品の写真に素材写真を混ぜると、**お客さんに実物と誤解させる**。だからサンプル以外では実物の枠に入れない
- **写真は直リンクせず、ダウンロードして素材置き場（④）に入れる**。素材サイトの画像URLを `file` に直接つなぐのではなく、手元に落としてから台帳に登録する（配信元の都合でリンクが切れる・規約に触れるのを避けるため）
- **選ばない写真**：**顔がはっきり写った写真**（肖像の権利・実在の人物と誤解させる）と、**ロゴが写った写真**（よその商標が入る）は選ばない

## 6. 下書き・公開・記録の持ち方（保存の仕組みの設計方針）

保存の仕組みはまだ作らないが、データの形に関わるので方針だけ決めておく。v4（2026-10-09）で、お店の方の編集（記録 15章）に合わせて書き直した。

| 持つもの | 中身 |
|---|---|
| お店の情報の下書き | ① 1つ（自動保存） |
| サイトの組み立ての下書き | ②③ 1つ（自動保存。直すたびに、操作が終わって 500ms 以内）。**今の形だけ**を持つ（4.9）。写真は④の ID で指す |
| 公開中の版 | ①②③ の組＋公開した日時・誰が |
| 公開した版の履歴 | 公開のたびに ①②③ の写し。新しい方から 30。各回に「お店の情報だけ」「サイト全体」の区別、誰が公開したか |
| 戻す前の下書き | 「この版を下書きにする」で置き換える前の下書きが公開中と違えば、その写し。新しい方から 10 |
| 最初の形 | 写しは持たない。テンプレートの名前と版から作る |
| 編集の設定 | お店ごと。最近使った色（`#rrggbb`、新しい順に5つまで）。版の写しに入れず、「公開中と同じか」の比べる対象にもしない（色を選んだだけで「まだ公開していない変更があります」にしないため） |
| 変更の記録 | いつ・誰が（オーナー／制作側／仕組み）・どの層の・どの場所を・前→後。確認待ちの解消もここに残る |

- **持たないもの**：戻すの記録（画面を開いている間だけ。PowerPoint と同じく、開き直したら空から。記録 10.1）。手直しごとの日時（8章）
- メニュー画面の「公開」は①だけ、編集画面の「公開」は①②③すべて（02の5.2）
- **状態の文字**（記録 15.2）：「まだ公開していません」／「公開中と同じです」／「まだ公開していない変更があります」。同じかどうかは、下書きと公開中の版の中身・手直しを比べて決める（直してから戻して元どおりなら「同じ」）
- **前の版に戻す**（記録 15.6・15.7）：履歴の版は見るだけ。「この版を下書きにする」で、その版の②③がまるごと下書きになる（公開中の版は変わらない）。①も戻すかは確認する（02の5.2）。「戻す」1回で取り消せる
- 変更の記録の「場所」は、review と同じくIDで指す（`/catalog/items/itm_monaka/prices`）

## 7. 書き起こしで出た7点の決定

**Q1. 空欄や長い文章で、要素が重なったり穴が開いたりするのをどう防ぐか → 伸び縮みの規則を入れる（4.3）**
- **v4 注記**：この狙いは変わらない。手段は、テンプレートの縦積み・付いていく先・間隔の決まり（4.8・4.10）に置き換わる。置き換わった後は、下の「h を必須にした」は外す
- 隙間を残す案は、オーナーがメールアドレスを消しただけで穴の開いたサイトが公開され、しかも本人は気づかない。重なりはもっと深刻で、品を足しただけで下の見出しに食い込む。どちらも問い合わせと手直しを生み、工数ゼロに反する
- 位置のデータを書き換えて詰める案は、「自由に置けて勝手に動かない」を壊す
- 表示のときだけずらす規則なら、両方を満たせる。規則は参照実装とテストで先に固めたので、検証の「わざと壊す」段階で、この規則が意図どおり効くかをそのまま確かめられる
- そのために、写真以外の要素に「配置したときの高さ h」を必須にした（あとから全店舗に足すのは難しい値なので、今決める）

**Q2. 年末年始などの決まった期間を形で持つか → 持つ。ただし予定された期間だけ**
- 年末年始の営業時間はお客さんが最も確認したい情報の一つで、形で持てばGoogleに渡す特別営業時間にもなる
- お知らせ機能にならないよう、素材集めでは「長期のお休み」としてだけ聞く。その年だけの期間は過ぎたら表示から消え、1年後に自動で削除する（古い予定が溜まって、オーナーが整理する手間を生まない）

**Q3. キャッチコピーを①に置くか → 2つに分ける**
- ①には「お店自身のひとこと紹介」（40字）。芦屋みっけの一覧カード、特集ページの店舗情報欄、検索結果の説明文の自動生成に使う事実
- サイトの大きなキャッチコピー（「季節を、ひと口に。」）は②の自由な文字。そのサイトのための言い回しなので連動させない（01の5.4どおり）
- 01の5.2と5.4の食い違いは、これで解消

**Q4. アレルギー表示を持つか → 持たない**
- 間違えれば健康被害につながり、一人の運営では内容の正しさを確かめられない
- 表示の対象品目は制度の見直しで変わってきた（くるみが義務表示の品目に加わった、など）。仕組みに一覧を持つと、その追従が保守として残り続ける
- 必要なお店は品の注記（「原材料についてはお店にお尋ねください」など）で足りる。本当に要ると分かれば、項目を足すのは既存のお店を壊さずにいつでもできる（2.6）

**Q5. 自宅で営業するお店の番地を隠す項目 → 持つ。①に置くので、すべての表示先に効く**
- 店舗調査でも、自宅で製造・営業している事業者や、集合住宅の一室で営業している事業者が見つかっている（CLAUDE.md「名簿の住所＝店舗の所在とは限らない」）。隠す手段がないと、そうしたお店の制作の相談に乗れない
- ①は1か所なので、公式サイト・芦屋みっけの掲載ページ・Googleに渡す構造化データのすべてで町名までの表示になり、地図は町の中心を指す。制作側の手元（裏取り）には番地を残す

**Q6. スマホの幅の違いの吸収 → 配置を作った幅を基準に、全体を比例で拡大縮小（4.2）**
- **v4 注記**：テンプレートの仕組みでもこのまま使う。手直しは 390 での px で持つので、公開前の確認・長すぎる文の目安を 390 で調べれば全機種に当てはまる。編集でも、どの機種で直しても同じ形が見える（PowerPoint のスライドが窓に合わせて縮むのと同じ）。縮めた中での書き換えは試験台でまだ確かめていない（4.11）
- 横だけ％・縦はpxの方式では、幅の広い機種で写真の上の文字がずれ、狭い機種で重なる。スマホも自由配置にした以上、機種によって崩れると、オーナーは「自分のスマホでは大丈夫なのに」と原因が分からない
- 比例の拡大縮小なら、デザインした見た目が全機種で保たれる。代わりに文字の大きさが機種によって約±10%変わるが、幅の狭い機種はおおむね画面そのものも小さく、広い機種は大きいので、手に持ったときの見た目の差は小さい
- 倍率の上下限を決め、タブレットのような広い画面で巨大化しないようにした

**Q7. 縦書きを材料に加えるか → 加える**
- 和菓子・料亭・和装・茶道教室など、芦屋で想定される業種の多くで、縦書きの見出しが「Studio級」の見た目を左右する
- 今ならデータに項目を1つ持つだけで済むが、表示の仕組みを作ったあとに足すと、文字の配置と4.3の規則の両方を作り直すことになる
- 崩れを防ぐため、縦書きの箱は大きさを固定（伸びない）とし、短い見出し・添え書き向けと割り切る

## 9. 検証（デザインの試作）でこの定義を使うときの手順

1. 参考サイトの分析から SPEC.md を作る（`reference_analysis_guide.md`）
2. 芦屋堂の `site.json`・`theme.json` を、そのデザインに合わせて書き直す（①④は原則そのまま使う）
3. `validate.mjs` を通してから、表示の仕組みで書き出す
4. わざと壊して、崩れた箇所を「材料を足す／データの形を直す／デザインの作り方」に振り分けて記録する。壊し方の候補：品名・説明を長くする、写真を抜く、品を30品にする、営業時間を空にする、括りを空にする、スマホ幅を360と430で見る、テーマ色を暗い色に変える
5. 「データの形を直す」になったものは、この定義を直して `schemaVersion` の扱いを判断する

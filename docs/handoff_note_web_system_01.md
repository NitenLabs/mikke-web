# 芦屋みっけ 引き継ぎメモ：Web制作システム編 01（編集体験とデータの形）

このメモは、③層（有料クライアント）向けWeb制作の「仕組み」を設計したセッションの決定事項をまとめたものです。これまでの `handoff_note_XX.md` が芦屋みっけ本体（メディア・店舗調査）を中心にしていたのに対し、本メモは**Web制作システムの設計**だけを扱います。

- ファイル名について：`CLAUDE.md` では `handoff_note_09.md` が最新とされていますが、このセッションのプロジェクト内には存在しなかったため、番号の衝突を避けて別系統の名前にしています。
- 関連ファイル：`editor_prototype.html`（編集体験の試作。公開版：https://claude.ai/artifact/BdKmyhRjj6Pzsk77psxsRW ）

---

## 0. このセッションで決まったことの要約

1. 納品後はオーナーが自分でサイトを編集する。目標は「リリース後の工数ゼロ」
2. 編集体験は「インスタの文字編集の迷わなさ」＋「Word・PowerPointの自由さ」。スマホでも自由に配置できる
3. PCとスマホは**中身が共通、位置・大きさ・形は端末ごとに別**
4. どのサイトも**決まった材料だけで組み立てる**。テンプレートでもオーダーメイドでも、オーナーの編集体験は完全に同じ
5. 制作も同じツールで行う（制作者モード／オーナーモード）。ただし保証の本体は「データの形が共通であること」なので、制作者モードの画面は後回しでよい
6. データは**4層（お店の情報／サイトの組み立て／見た目の設定／素材置き場）**に分ける
7. 素材集め（ヒアリング）は既存の `hearing_flow_connected.html` にとらわれず、一から設計し直す

## 1. 前提と大方針

### 1.1 事業上の前提
- 運営は一人。**リリース後は工数がかからない**ことを最優先する
- そのために、納品後はオーナー自身が編集できる仕組みを用意する
- 参考にする編集体験は Studio.Drop（2026年9月1日発表、クローズドβ）のうち、**見たまま編集する「Design Mode」側**。AIによる編集機能（AI Edit）はAPI費用が継続的に発生するため採用しない

### 1.2 デザインの作り方
- Studioの既存テンプレートや他サイトを参考にするが、**参考にするのは構造（グリッド、余白のリズム、情報の並び順など）まで**。配色・装飾・イラスト・コピー・固有のあしらいを見た目ごと再現することはしない（著作権・利用規約のリスク）。これは `CLAUDE.md` の「新しいテンプレートは実在する参考メディアの構造分析から始める」と同じ方針
- 骨格の数は `business_operations_blueprint.md` の方針どおり10〜20種類を目安とし、「全部模倣」はしない

### 1.3 テンプレートとオーダーメイド
- **テンプレート制作とオーダーメイド制作の両方を想定する**
- 両者の違いは「材料の組み合わせ方を、あらかじめ用意しておくか、そのお店のために一から組むか」だけ。使う材料は同じ
- 評判の良かったオーダーの構成は、そのまま新しいテンプレートとしてカタログに加えられる

## 2. 編集体験の決定事項

### 2.1 PCとスマホの扱い
| 種類 | PCとスマホで | 例 |
|---|---|---|
| 中身 | **共通**（どちらで直しても両方に反映） | 文章、写真そのもの、メニュー、リンク先、フォント、色、行間 |
| 配置 | **端末ごとに別** | 位置、幅・高さ、文字の大きさ、写真の枠の形、線の太さ |
| 表示 | 端末ごとに表示・非表示を切り替え可 | 「PCでは飾りの写真を出すが、スマホでは省く」 |

- スマホも**自由配置**（オーナーの要望。「スマホは固定」案は不採用）
- スマホの初期配置は**制作時にデザイン済み**の状態で渡す（Squarespaceの「スマホは追加順に並ぶだけで崩れる」問題が、そもそも起きない）
- 位置は画面幅に対する割合で保存し、機種ごとの幅の違い（360〜430px程度）に対応する
- タブレットはPCかスマホのどちらかに寄せ、3つ目のレイアウトは作らない
- 編集画面の上部に「いま編集中：スマホ　位置と大きさはスマホだけに反映」のように、どちらの端末を編集しているかを常に表示する

### 2.2 基本操作（選択と移動）
- 手本は**インスタのストーリーズの文字操作**（オーナーが日常的に慣れている操作）と**PowerPoint**
- **スマホ**：1回タップで選択、選択中の要素だけ指で動かせる。選択していない場所をなぞるとスクロール（長押しで掴む方式は、気づきにくいので不採用）
- **PC**：クリックしてそのままドラッグで移動できる（PowerPointと同じ）
- **2回目のタップ**：文字は「書き換え」に入る。写真は「下に重なっている要素に選択を切り替える」
  - 当初は「同じ場所をもう一度タップすると下の要素」と決めていたが、試作で文字の書き換えと衝突することが分かり、上記に変更した
- **吸着とガイド線**：セクションの中央線、他の要素の端・中央、テンプレートで設計した余白ラインに近づくと吸い付き、線が出る。グリッドにはめる方式ではなく「自由に置けるが整った位置に吸い寄せられる」方式
- **微調整**：スマホは「⋯」内の十字ボタン（1px／10px切り替え）。**PCでは微調整ボタンは出さず**、マウスでの直接操作と矢印キー（Shiftで10px）で行う
- 移動はセクションの中まで。下端まで動かすとセクションが自動で縦に伸びる
- ある要素の文章が長くなっても、他の要素の大きさが勝手に変わることはない（Squarespaceで起きている連動の副作用を避ける）

### 2.3 拡大縮小
- 選択すると**四隅と四辺の8つのつまみ**が出る（要素が小さいときは、指で押せるよう辺のつまみを省く）
- **写真**：角は縦横比を保ったまま拡大縮小、辺は枠の形そのものを変える（写真は枠に合わせて自動で切り抜かれ、歪まない）。辺で変えた形は「自由な形」として保存される
- **文字**：左右で幅、上下で高さ。文字が入りきらない高さにはできない
- **図形**：自由に変形。線は長さ（左右）のみ

### 2.4 範囲選択とまとめて操作
- **PC**：何もない所からドラッグで囲む。**囲みの中にすっぽり入った要素**が選ばれる（PowerPointと同じ判定）。Shift＋クリックで追加・解除
- **スマホ**：何もない所を**長押ししてから指を動かす**と範囲選択（通常のスクロールと区別するため）
- ロック中の要素は範囲選択に含めない
- まとめて選んだ状態でできること：一緒に動かす、配置（左・左右中央・右・上・上下中央・下にそろえる、横／縦に等間隔）、複製、ロック、削除

### 2.5 ロックと非表示
- **ロック**：鍵のボタンで、位置と大きさを固定。文字の書き換えや写真の差し替えはロック中でもできる。背景に敷く写真は最初からロックしておく
- 以前あった「位置固定」（テンプレート側で動かせない要素）は**廃止**し、すべての要素を動かせるようにした。動かしたくないものはロックで対応する
- **端末ごとの非表示**：「⋯」の「表示する端末」で切り替え。非表示の要素は編集画面では斜線入りの半透明で残し、消えたと勘違いさせない

### 2.6 文字の編集（Word・PowerPointの感覚）
- 書き換えは、選択した文字をもう一度タップ。スマホでキーボードが出たら、書いている文字が隠れないよう画面が自動で動く
- ツールバー：PCは上部、スマホは画面下（PowerPointのスマホアプリのような配置）
- **文字の大きさ**：数字で自由に指定（直接入力／＋−／一覧から選択）。端末ごとに別。スマホで12未満にすると「読みにくいかもしれません」と控えめに知らせる
- **フォント**：多めに用意（明朝体・ゴシック体・丸ゴシック体・手書き/個性的・欧文の計約30種）。一覧ではフォント名をそのフォント自体で表示する。**サイトで実際に読み込むのは使っているフォントだけ**（日本語フォントは重いため）
- **色**：PowerPointと同じ構成。「このサイトのテーマ色」「最近使った色」「標準の色」「その他の色（自由に作る）」。背景と近い色で読みにくいときは知らせる
- **装飾**：太字・斜体・下線（日本語の斜体はブラウザが機械的に傾けるため、英字ほど綺麗ではない）
- **揃え**：左・中央・右
- **段落**：行間、文字間隔（PCとスマホ共通）、箇条書き（・／番号付き）
- **効果**：影（やわらか／くっきり）、縁取り。写真の上に文字を置くときの読みやすさ対策
- **一部だけの装飾**：文章の一部をなぞって選ぶと「選択した部分に適用」と表示され、その部分だけフォント・大きさ・色・太字などを変えられる。何も選んでいなければ文字の箱全体に効く
  - 部分的な大きさは「周りの文字の何倍か」で保存するため、PCとスマホで全体の大きさが違ってもバランスが保たれる
- **リンク**：文字の一部または箱全体に付けられる。種類は「ウェブページ・電話・メール・Instagram」。Instagramはユーザー名、電話は番号を入れるだけで正しい形に自動変換。入力ミスはその場で知らせる。編集中はリンクを押しても移動しない（プレビューで確認できる）
- **日本語の改行**：単語（文節）の区切りで自然に折り返す仕組みを最初から入れる。オーナーに改行位置を直させない
- 文章が長くなったら、文字の箱は縦に伸び、必要ならセクションも伸びる

### 2.7 写真の編集
- **写真を変更**：「アルバム・カメラから選ぶ」と「これまでの写真（写真ライブラリ）」から選ぶ。アップした写真はライブラリに残り、季節ごとに入れ替えて戻すこともできる
- **トリミング**：枠の中で写真をずらし、拡大率を変えて、見せる範囲を決める（PowerPointの「トリミング」と同じ）
- **形**：元の写真の比率・正方形・横長・縦長など（端末ごとに別）。辺のつまみで自由な形にもできる
- **角の丸み**：0〜100%（100%で円やカプセル形）
- **補正**：明るさ・コントラスト・鮮やかさ、ワンタップの「自動補正」、元に戻す
- **暗くする**：写真の上に置いた文字を読みやすくするための暗さの調整
- **説明**：検索エンジンや読み上げ機能向けの説明文（任意）
- **自動で行う裏側の処理**：iPhoneの写真形式（HEIC）の変換、表示に適したサイズへの縮小・圧縮、向きの修正、**撮影場所の位置情報の削除**（自宅で作業しているお店への配慮）
- 枠に対して解像度が足りないときは「ぼやけて見えるかもしれません」と知らせる

### 2.8 図形
- 種類：四角・丸・線
- 設定：塗りの色、角の丸み（四角）、透明度、線の太さ（線、端末ごと）

### 2.9 その他の操作
- **書式のコピー**：筆のボタンを押してから別の要素をタップすると、装飾だけが写る（PowerPointの書式のコピーと同じ）。同じ種類の要素どうし（文字→文字、写真→写真、図形→図形）のみ
- **複製・コピー・貼り付け・削除**：PCはCtrl+D／C／V、Deleteキー、Ctrl+Aでセクション内をすべて選択。スマホは「⋯」内に「複製」「左右の中央に配置」
- **重なり順**：前面へ・背面へ
- **追加**：画面右下の＋から、文字・写真・図形を追加。いま見ているセクションに追加され、もう一方の端末にも自動で追加される（位置はそれぞれ調整）
- **背景**：何も選んでいないときのツールバーの「背景」から、画面中央のセクションの背景色を変える（対象のセクションが一瞬光って知らせる）。背景を変えて読みにくくなる文字があれば、その数を知らせる。「写真を背景に敷く」で、写真をセクション全体に広げて一番奥に置き、ロックして少し暗くするところまで自動で行う
- **プレビュー**：選択枠や非表示の要素を消して、お客さんが見る状態を確認する。リンクもここで実際に押せる

### 2.10 保存・公開・取り消し
- 編集内容は**自動で下書き保存**。「公開」を押すまで実際のサイトには反映されない
- 元に戻す・やり直し（編集中の細かい操作）
- **公開履歴**から「この状態に戻す」ができる。戻した内容は下書きになり、確認してから公開する。テンプレートの初期状態にも戻せる

### 2.11 検討したが採用しなかったもの
| 項目 | 不採用の理由 |
|---|---|
| AIによる編集（Studio.DropのAI Edit相当） | API費用が継続的に発生する |
| スマホは固定配置／型を選ぶ方式 | オーナーの理想の編集体験を優先し、スマホも自由配置にした |
| ボタン専用の部品 | 図形＋文字＋リンクで同じものが作れる。部品を増やさない方が覚えることが少ない |
| スマホ画面下の固定バー（電話する・予約する） | 同上 |
| 回転・アニメーションの編集 | お店のサイトでの使いどころが少なく、崩れる原因になりやすい |
| オーナーによるセクション・ページの追加や移動 | 大きい編集は想定しない（制作側に依頼してもらう） |
| 臨時休業などのお知らせ機能 | `handoff_note_03.md` の方針を継続（即時性の高い情報はSNS・LINEに任せる） |
| 地図やInstagramなどの埋め込みを編集画面で自由に扱うこと | 崩れやすい。**埋め込みはテンプレート・納品時にこちらで組み込む**。オーナーは位置・表示非表示のみ |

## 3. 仕組みの大方針

### 3.1 どのサイトも決まった材料だけで組み立てる
- お店によって項目もレイアウトも違うが、材料（文字・写真・図形・繰り返す部品・共通部分・埋め込み・動き・フォーム）だけで作っておけば、編集画面はそのサイトのレイアウトを知らなくても、同じ操作で編集させられる
- **新しいデザインで今の材料では作れない表現が出てきたら、そのサイトだけ特別に作り込まない。材料を1つ増やし、その材料の編集方法も同時に決める**。これを守る限り、何を作っても同じ編集体験が保てる

### 3.2 制作も同じツールで行う
- ツールに「制作者モード」と「オーナーモード」を持たせる（Studio自体がこの構造）
- 制作者モードではセクションの追加、繰り返す部品の設計、動きの設定などもできる。納品時はオーナーモードで渡す
- ただし、同じ編集体験を**保証しているのは画面ではなく「データの形が共通であること」**。なので当面は、オーナーモードの画面をしっかり作り、**制作者モードは画面を作らず、Claude Codeが同じ形のデータとしてサイトを書き出す**形で十分。制作者モードの画面は、制作件数が増えて必要になってから作る

### 3.3 この方針の注意点と手当て
| 注意点 | 手当て |
|---|---|
| ツール自体が大きな開発になる | 上記3.2のとおり、制作者モードの画面は後回しにする |
| 表現できるデザインに上限ができる | Studio級のデザインを1つこの仕組みで作り、早めに限界を確かめる（未実施） |
| 見た目以外の品質（検索エンジン・読み上げ）を忘れやすい | 文字に「見出し・小見出し・本文」の役割を持たせる、読む順番を位置から自動で決める、写真を自動で軽くする |
| ログイン・保存・バックアップ・公開を自前で運用する | パスワードを忘れても自分で入り直せる、壊しても履歴から戻せる、など「オーナーが自己解決できる仕組み」を最初から揃える |

### 3.4 実装の時期
- `business_operations_blueprint.md` では、Web制作の仕組みの本格実装は「制作クライアントが数件確保できてから」としていた。この方針は変えない
- 最初のクライアントの時点で全部揃っている必要はなく、オーナーモードの中核と公開の仕組みがあれば納品できる
- 今やるべきは「材料とデータの形の定義」と「Studio級のデザインで破綻しないかの確認」まで

### 3.5 PC画面の幅
- 実際のPC画面は幅がまちまちなので、**中身は中央の決まった幅に収め、背景や写真だけ画面いっぱいに広げる**作り方にする（試作は幅1100px固定のため未対応）

## 4. 制作の全体の流れ（8段階）

```
お店と出会う → 素材を集める → 型を選ぶ（テンプレート／オーダー） → サイトを組む
→ 確認・修正 → 公開 → 自分で更新 → 月額で継続
```

| 段階 | 主に動く人 | 現状 |
|---|---|---|
| お店と出会う | 制作側 | 芦屋みっけの3層構造で入口の設計はできている |
| 素材を集める | オーナー | **一から設計し直す**（既存の `hearing_flow_connected.html` は前提にしない） |
| 型を選ぶ | 制作側 | テンプレートカタログの考え方はある。Webサイト側のテンプレートは1種類のみ、カタログのファイルは所在不明。オーダーメイドも選択肢に加わった |
| サイトを組む | 制作側 | 本メモの「材料」と「データの形」が土台 |
| 確認・修正 | オーナー | 未着手 |
| 公開 | 制作側 | 未着手（ドメインの扱いを含む） |
| 自分で更新 | オーナー | 本メモの編集体験と試作が土台 |
| 月額で継続 | 制作側 | 未着手（料金、支払い方法、解約時にサイト・ドメイン・データをどう扱うか） |

## 5. データの形（6項目、すべて決定）

### 5.1 4層に分ける
| 層 | 中身 | 例 |
|---|---|---|
| ① お店の情報 | 見せ方と関係ない、お店にひとつだけの事実 | 店名、営業時間、定休日、電話、メニュー |
| ② サイトの組み立て | どこに何を置くか | 「2番目のセクションの左6%・上156pxに、幅42%の文字の箱で営業時間を表示」 |
| ③ 見た目の設定 | サイト全体の雰囲気 | テーマ色、見出しのフォント |
| ④ 素材置き場 | 写真の実物 | お店から預かった写真 |

- ①を②から切り離すことで、芦屋みっけの掲載ページ、特集ページ、Webサイトのすべてが同じお店の情報を参照できる（ブループリントの「取材は1回、出力は複数」の実現）
- 営業時間を1か所直せば、表示しているすべての場所が変わる
- たとえ：①は冷蔵庫の食材、セクションは料理。同じ食材から、見せ方の違う料理がいくつもできる。食材を持っていても料理に使わないことはある
- **どんなセクションを用意するかは①ではなく②の話**で、テンプレートやオーダーでサイトを作るときに決める

### 5.2 お店の情報の項目
- 考え方：「サイトに載せるかどうか」ではなく「お店の事実として持っておくかどうか」で決める。**分からない項目は空欄のままでよく、空欄は自動で表示しない**（芦屋みっけのスポットページと同じ）
- **共通項目**：
  - 基本：店名、読み方、業種、キャッチコピー
  - 場所：住所、最寄り駅からの行き方、駐車場の有無
  - 時間：営業時間、定休日、年末年始などの補足
  - 連絡：電話番号、予約の方法（電話・Web・LINEなど）と予約ページのURL、メールアドレス、SNSのアカウント
  - その他：支払い方法、設備（席数、子ども連れ・車椅子の可否など）、物語（創業年、店主のこだわりなど）、よくある質問
- **業種ごとの違いは3か所に集中する**：「どんなリストを持つか」「リストの1項目が何を持つか」「その業種ならではの情報」

| 業種 | 持つリスト | リストの1項目が持つもの | その業種ならではの情報 |
|---|---|---|---|
| 飲食 | メニュー、コース | 価格、テイクアウト可否、アレルギー | 席数、喫煙、予約の要否 |
| 物販 | 商品 | 価格、季節限定かどうか | 通販・配送の有無、取り置き |
| 美容・理容 | 施術メニュー、スタッフ | 価格（〜円）、所要時間 | 予約サイト、指名料 |
| 医療・歯科 | 診療案内、医師紹介 | 保険・自費の別 | 診療科目、午前・午後の診療時間、休診日 |
| 整体・治療院 | コース | 価格、所要時間 | 保険の取り扱い、初回の流れ |
| 教室・習い事 | クラス、講師 | 曜日・時間、対象年齢、月謝 | 体験レッスン、入会金 |
| 士業・サービス | サービス | 料金の目安 | 資格、対応エリア、相談の流れ |

- **リストの形は1種類**：1項目は必ず「名前・説明・写真・分類」を持ち、業種ごとに「価格」「所要時間」「曜日・時間」などを追加できる。これはサイト側の「繰り返す部品」とそのまま対応する
- **業種ごとの項目のひな形**を用意する。芦屋みっけの店舗データの業種分類（roster.genre）から自動で選ばれ、ヒアリングも「その業種で聞くべきこと」だけになる。当てはまらないお店は共通項目＋自由項目で対応
- **芦屋みっけの店舗データと同じお店として紐づける**。住所・電話番号など裏取り済みの情報は、制作が決まった時点で最初から入った状態にする
- **営業時間**：曜日ごとの決まった形で持ち、**1日に複数の時間帯**（ランチ／ディナー、午前／午後）を持てるようにし、収まらない部分は**補足の自由記入欄**に書く（両方持ち）
- **価格**：数字に加えて「〜」「時価」「応相談」などの表記も持てる形にする
- **医療・歯科・治療院の注意**：医療広告のガイドラインにより、患者の体験談や施術前後の比較写真などは原則として掲載できない。ひな形に注意事項を持たせ、編集画面で知らせる（実際の線引きは制作時に専門家へ確認）

### 5.3 抜け漏れが出たときの影響（判断の根拠）
| 抜け漏れの種類 | 影響 | 理由 |
|---|---|---|
| 項目そのものが足りない | 小さい | オーナーは自由な文字として書ける。気づいた時点でひな形に足せば、既存のお店は空欄＝非表示なので何も壊れない |
| 持ち方の形を間違える | 中くらい | 全店舗のデータ変換が必要になる（例：価格を数字だけで持つと「時価」が入らない） |
| 層の分け方を間違える | 大きい | 仕組み全体の作り直しに近い |

- よって、**項目の完璧な洗い出しより、持ち方の形（営業時間、価格、リストの1項目、写真と項目の紐づけ）を正しく決めることを優先**する。個々の項目は、最初のクライアントを何件か作る中で見つかったものを足していく
- 項目を足したときは、既存のお店のオーナーに「新しく登録できる項目が増えました」と知らせる

### 5.4 サイトとお店の情報の連動
- サイトの文字は「**お店の情報と連動している文字**」と「**自由な文字**」の2種類
  - 連動させる：営業時間、定休日、住所、電話番号、価格、メニューなど、間違っていると実害が出る事実
  - 連動させない：キャッチコピー、「店主より」など、そのサイトのための言い回し
- 連動している文字も、操作は自由な文字と同じ（フォント・色・位置は自由）。中身を書き換えると①が書き換わり、同じ情報を使うすべての場所に反映される。選択時に「お店の情報と連動しています。書き換えると芦屋みっけの掲載ページにも反映されます」と表示する
- 「この場所だけ別の文章にする」で連動を外せる（あとから戻せる）
- **繰り返す部品はお店のリストと連動**。サイト上でメニューを1品足せば、お店のメニューリストに1品増える。部品ごとに「どの分類を」「何件まで」「どれを選んで」表示するかを決められる
- 連動している文字の中身が空欄なら、公開サイトでは自動で非表示。編集画面では「（営業時間が未登録です）」と薄く表示して入力を促す
- **反映のタイミング**：お店の情報の書き換えも下書き扱い。**「公開」を押したときに、サイトと芦屋みっけへ同時に反映**する（「公開を押すまで、どこにも出ない」という1つのルール）。取り消しや履歴にもお店の情報の変更を含める
- **連動を外した場所の置き去り対策**：元の情報が変わったら「連動を外している場所が1か所あります。古い内容のままかもしれません」と知らせ、その場所へ飛べるようにする
- **写真は連動させない**：素材置き場で共有するが、どこにどの写真を使うかは場所ごとに自由。サイトで写真を差し替えても特集ページの写真は変わらない。どこかで使われている写真を素材置き場から消そうとしたら「〇か所で使われています」と知らせる
- **芦屋みっけの裏取りルールとの関係**：オーナー本人の書き換えは一次情報としてそのまま反映する。ただし変更の記録を残し、制作側が後から確認できるようにする（反映を止めるのではなく、あとで見られるだけ）

### 5.5 材料の一覧
すべての材料に共通する操作：位置と大きさ（端末別）、重なり順、ロック、端末ごとの非表示、複製・削除、範囲選択、書式のコピー。

| 材料 | オーナーが触れること | 制作時にこちらが決めること |
|---|---|---|
| 文字 | 中身、フォント、大きさ（端末別）、色、太字・斜体・下線、揃え、行間、文字間隔、箇条書き、影・縁取り、リンク、一部だけの装飾、連動の解除・復帰 | 文字の役割（ページの見出し・小見出し・本文） |
| 写真 | 差し替え、トリミング、形（端末別）、角丸、補正、暗くする、説明文 | 最初の配置と形 |
| 図形 | 種類（四角・丸・線）、塗りの色、角丸、透明度、線の太さ | 最初の配置 |
| 繰り返す部品 | 項目の追加・削除・並べ替え・書き換え、表示する分類と件数、カード内の配置と装飾（全カードに反映） | どのリストと連動するか、最初のカードのデザイン、横に何列並べるか（端末別） |
| 共通部分（ヘッダー・フッター） | 中の文字・写真・図形を普通に編集（全ページに反映） | ヘッダーとフッターの構成 |
| ページ移動のメニュー | 並び順と表示名 | ページの一覧から自動生成。スマホでは三本線のボタンで開閉 |
| 埋め込み（地図など） | 表示・非表示、位置と大きさ | 何を埋め込むか |
| 動き | オン・オフ | どの要素にどんな動きを付けるか |
| フォーム | 使う・使わない、項目の選択と並べ替え、必須かどうか、送信先メール、自動返信の文面 | 最初の配置 |
| セクション | 背景の色、背景に写真を敷く | セクションの追加・削除・並び順 |

- **スライドショー**は独立した材料にせず、「繰り返す部品を、並べる代わりに順番に切り替えて見せる」見せ方の1つとして扱う。オーナーの操作は写真のリストの追加・差し替えだけ
- **フォームの詳細**：
  - 店が「使う・使わない」を選べる（ヒアリング時に選び、公開後もオーナーがオン・オフできる）
  - 一から組み立てる方式にはせず、「お問い合わせ」「予約のご希望」の2種類のひな形から項目（お名前・電話番号・メールアドレス・希望日時・人数・ご用件など）を選ぶ。見た目はテーマ色・フォントに自動で合わせる
  - 届いた内容はオーナーのメールに送るのに加え、**編集画面内の受信箱にも残す**（迷惑メールに振り分けられても取りこぼさない）
  - 迷惑な自動送信の対策は、Cloudflareが無料で提供する、お客さんにパズルを解かせずに機械の送信を見分ける仕組みを使う
  - 送信者への自動返信あり（文面はオーナーが変更可）
  - フォームをオンにすると**プライバシーポリシーのページが自動で作られる**（店名などを差し込んだ標準文面。最終的な文面は専門家に確認）
  - 「予約のご希望」フォームには、フォームの上と自動返信に「お店からの連絡をもって予約確定となります」を必ず入れる。すでに予約サービスを使っているお店は、そちらへのリンクを案内する

### 5.6 ページの構成
- **ページの追加は制作側**。オーナーは各ページの**公開・非公開の切り替え**と、メニューでの**表示名・並び順の変更**まで
- **ページのアドレスは自動**（トップは「/」、メニューは「/menu」など）。途中で変わるとリンク切れが起きるため、オーナーは触らない
- ページごとに**検索結果のタイトル・説明文、SNSやLINEで共有したときの画像**を持つ。お店の情報から自動生成し（例：「御菓子司 芦屋堂｜芦屋市・阪神芦屋駅の和菓子店」）、オーナーが書き換えることもできる。編集画面で「Googleではこう見えます」「LINEではこう見えます」を見せる
- **裏側で自動で用意するもの**：Googleにお店の住所・営業時間・電話を正確に伝える情報（お店の情報から自動生成）、検索エンジン向けのページ一覧、ページが見つからないときの案内ページ、ブラウザのタブのアイコン（ロゴから自動生成）、フォーム利用時のプライバシーポリシー
- **芦屋みっけとの相互リンク**：掲載ページ→お店のサイト、お店のサイトのフッター→掲載ページを自動で張る
- 決めていないこと：ドメイン（公開・料金の段階で決める）、多言語化（余地だけ残す）

### 5.7 版の管理
- 持つ版は3種類：**下書き**（自動保存、1つ）、**公開中の版**（1つ）、**過去に公開した版**の履歴
- 履歴から戻すと下書きになり、公開で反映。お店の情報の変更も同じ版に含む
- 取り消し・やり直しは、編集中の細かい操作用として別に持つ
- 履歴の保存数：直近30回分、または1年分などを目安に、保存容量との兼ね合いで実装時に決める
- 「いつ、誰が（オーナーか制作側か）、何を変えたか」の記録を残す（5.4の芦屋みっけ反映の確認にも使う）
- **写真のゴミ箱**：素材置き場から削除した写真は一定期間（例：30日）残し、古い版に戻したときに写真が欠けないようにする
- **同時編集**：
  - オーナーが複数の端末で同時に編集している場合は「別の端末で編集中です」と知らせる
  - 制作側がページの追加などを行うときは、オーナーの未公開の下書きの上に加える形にし、編集画面に「制作側でページを追加しました。公開すると反映されます」と知らせる。オーナーの作業途中の内容は消えない

## 3. A. Chrome の変換の信号で再現する試験

### 3.1 やり方

- 変換の信号は、Chromium の CDP で送る：変換中は `Input.imeSetComposition`（`text`・`selectionStart`・`selectionEnd`）、決めるときは `Input.insertText`。**`keyboard.type` や、スクリプトでの文字の書き換えに置き換えない**
- 変換中の1回ごとの信号の後に 100ms 待ち、その時点の値を取る
- 毎回取る値：
  - 打っている文字の箱と、**同じセクションのすべての `[data-el]`** の位置と大きさ（`getBoundingClientRect` の x・y・w・h）
  - セクションの高さ、ページ全体の高さ
  - 打っている文字の箱の中の文字（`textContent`）
- ページの中で `compositionstart`・`compositionupdate`・`compositionend`・`input`（`isComposing` も）を記録し、どの順で届いたか出す。届かないときはそこで止める
- `pageerror` をすべて出す
- 窓：PC は 1440×1100。スマホでの編集は 390×844・`hasTouch`（`inputMode()` が `'phone'` になることを先に確かめる）
- headless と、画面を出した Chrome（headed）の両方で走らせる

### 3.2 試験

| # | 場所 | 操作 | 出すもの |
|---|---|---|---|

## 4. B. Mac の本物の日本語入力を動かす試験

### 4.1 始める前に確かめること（どれか欠けたら、そこで止めてユーザーに伝える）

1. 日本語の入力ソース（ローマ字入力）が入っているか。`defaults read com.apple.HIToolbox AppleEnabledInputSources` などで見る
2. ターミナル（Claude Code を走らせているアプリ）に、アクセシビリティの許可があるか。`osascript -e 'tell application "System Events" to keystroke ""'` が通るかで見る
3. 欠けていたら、**何をどこで許可すればよいかを短く書いて止める**。自分で設定を変えない

### 4.2 やり方

- Playwright で画面を出した Chrome を開き、特集の本文をダブルクリックして書き換えの状態にする
- 入力ソースを日本語にする（`osascript` で Ctrl+Space など。切り替わったかは画面の写しで確かめる）
- `osascript` の System Events の `keystroke` で、ローマ字を1文字ずつ 150ms ごとに打つ。変換はスペース、決めるのはリターン
- 打っている間、Playwright 側で 50ms ごとに 3.1 と同じ値を取り続ける
- 試験：I1（`kashiwo` → スペース → リターン）、I2（長い文をローマ字で打って決める）、I3（変換中に Esc）、I4 の前半（5回）と Cmd+Z。候補の窓が出ているときの画面の写しも撮る
- 終わったら入力ソースを元に戻す

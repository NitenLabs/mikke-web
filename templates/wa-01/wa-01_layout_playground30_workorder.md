2. `bash tools/verify-audit/run_audit.sh <試験台28 の絶対パス>` → **全体 OK 2 / NG 133**（項目 135 ＝ J 57・P 29・F 49。OK の2つは P5 と F57）になることを確かめる

4. `bash tools/verify-claudeai/run_all.sh <試験台29>` と、run_all.sh に入っていない `verify_extra_save.py`・`verify_extra_catalog.py`・`verify_extra_pages.py`・`verify_extra_align.py`・`verify_extra_width.py` を **試験台29** に走らせ、NG の一覧を `refs/compare/layout/playground30/baseline_29.txt` に残す（「増えた NG」の基準。試験台29 の report.md と同じはず）

### 2.2 1項目ずつ
§3 の順に、1項目（または同じ原因の数項目）ずつ：
1. 直す
2. その項目を `run_audit.sh <試験台30> <area>` か、スクリプトに ID を渡して走らせ OK を確かめる。同じ area の全部も走らせ、ほかが NG に戻っていないこと
3. コミット（頭に ID。例 `試験台30 P2: 押して離すで書き換え、ドラッグで動かす`）
4. report.md の済の表に1行

### 2.3 区切りごと（§3 の小見出しごと、または10項目ごと）
- `run_audit.sh <試験台30>`（8本全部）
- tools/verify-claudeai の全スクリプトを試験台30 に。**baseline_29 より増えた NG が 0**（§1 の「古い確認の直し」で直した項目は除く）
- push

### 2.4 終わり
- §3 の項目がすべて「済」か「保留」
- §5 の合格の基準を満たす
- report.md を仕上げ、コミット・push して止まる

### 2.5 止まらないための決まり
- 1項目に **3回直しても OK にならない**、**直すと別の合格が壊れて両立できない**、**ユーザーが決めることがこの作業票にも PowerPoint にも無い**、のどれかなら「保留」にして report.md に理由・試したこと・ユーザーに決めてほしいことを書き、**次へ進む**。直しかけは戻してからコミット
- 揺れる確認は3回走らせて多い方。揺れたことを報告に
- 止まるのは：§1 の前提が満たせない、§2.1-2 の数が合わない・§2.1-3 で空振りを疑う、作業そのものが続けられない、のどれかだけ

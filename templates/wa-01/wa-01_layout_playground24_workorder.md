## 1. 何を変えるか

今の試験台は、操作の記録の列（`ops`）を保存している。版の履歴も版ごとに `ops` と写真のデータそのものを持つ。これを DATA_SPEC 6章のとおりにする。

| | 今（試験台23） | 試験台24 |
|---|---|---|
| 下書き | `{ops, assets}` | 今の形（4.9）＋ `seq` |
| 版・戻す前の下書き | 版ごとに `ops` と写真のデータ | 版ごとに今の形。写真は ID で指すだけ |
| 写真のファイル | 下書き・版ごとに写す | 写真の入れ物に ID ごとに1つ（5.2） |
| 戻すの記録 | 保存する（開き直した後は undoBase まで） | 保存しない。開き直したら空から（記録 10.1） |
| 公開中と同じか | `ops` の列どうしを比べる | 今の形どうしを比べる（6章：直してから元どおりにしたら「同じ」） |
| 最近使った色 | 画面の中の変数だけ | 「編集の設定」として保存。比べる対象にしない |

## 2. 作ること

### 2.1 土台と記録

- 状態に **土台**（`state.base`＝4.9 の形の下書き。最初はテンプレートの初めの形＝空の下書き）を持つ
- `reduce(ops, device, peek)` は、**土台から始めて** `ops` を畳む。土台を `reduce` の中の入れ物（`m1`・`m2`・`order`・`sizes`・`zmap`・`colsMap`・`swapMap`・`viewAll`・`textStyles`・`runsMap`・`editMap`・`replaceMap`・`clearL`・`brightMap`・`linkMap`・`adds`・`removed`・`secList`・`secContent` など）に流し込む関数（以下 **seed**）を作る
- 反対に、土台と `ops` から今の形を作る関数（以下 **fold**）を作る。PC とスマホの両方で畳んで、1つの下書きにまとめる
- `ops`・`cursor`・`undoBase` は土台の後の操作だけを持つ（画面を開いている間だけ）

### 2.2 今の形の中身（4.9 への対応）

| reduce の入れ物 | 下書き（4.9） |
|---|---|
| `secList` | `sections: [{id, type, from?}]`（`feature`・`items` は `from` を書かない） |
| `editMap`・`runsMap` | `content[部品ID]`：見た目のない文字は文字列、ある文字は切れ目の並び |
| `replaceMap`・`clearL`・`brightMap` | `content[部品ID]`：`{asset?, cleared?, bright?}` |
| `linkMap` | `content[部品ID].link` |
| `adds`（消していないもの） | `added: [{id, kind, from?, placedOn, anchor}]` |
| `removed`・消したセクション・消した品／表の行 | `removed` |
| `m1` | `adjust[端末][部品ID].move: {dx, dy}` |
| `m2` | `adjust[端末][部品ID].place: {after, gap, x}` |
| `order`・`swapMap`・`sizes`・`zmap`・`colsMap`・`viewAll` | `adjust[端末]` の並び順・左右の入れ替え・大きさ・重なり順・列・`view` |
| `textStyles` | `textStyle` |
| （新） | `seq: {sec, add}`：次に使う連番。セクション（`sec*`）と足した部品・複製した品（`add_*`・`addp_*`・`c_dup*`）。消しても減らさない |
| （新） | `template: {name: "wa-01", version: 1}` |

- **4.9 の形に入らない情報**は、勝手に捨てず、下書きの `_pg` の中に入れる。少なくとも次は入りそうにない。どう持ったかと、なぜ 4.9 に入らないかを報告の一覧に書く（Claude.ai がそれを見て、DATA_SPEC に足すか、動きの方を 4.10 に合わせるかを決める）
  - 足した部品の `wOther`・`hOther`・`styleName`・`placed`・`gap`・`x`、`placedCleared`・`placedFollow`
  - 足した品・表の行の中身と並び（4.11 の④がまだ決まっていないため）
  - 重なり順を 4.9 の「並び」に直すと失うものがあれば、その数字
- `op.t === "template"`（`tpl`）は今どこからも積まれていない。使っていなければ捨ててよい（報告に書く）
- **何もしていない所は書かない**（2.1）：`dx`・`dy` が 0 の `move`、明るさ 0、テンプレートと同じ文字、空の `adjust` などは書かない。キーの順を決めて並べ、同じ中身なら同じ文字列になるようにする

### 2.3 保存

- IndexedDB の名前は `mikke-playground24`。試験台23 の保存は読まない（変換は作らない）
- 鍵は4つ
  - `draft`：今の形（`fold(state.base, activeOps())`）
  - `versions`：`[{id, kind, at, draft}]`（`kind` は `initial`・`published`・`beforeRestore`。数の上限は今のまま。`initial` は中身を持たない）
  - `assets`：写真の ID → データ（テンプレートの写真は入れない）
  - `settings`：`{recentColors: [...]}`
- 保存の時機（`scheduleSave`）・状態の文字・失敗の扱いは今のまま
- **写真の入れ物**：保存のたびに、下書き・すべての版が指している写真の ID を集める。入れ物に無いものは足し、どれにも指されていないものは消す（5.2）

### 2.4 開く

- `draft` を土台にし、`ops = []`・`cursor = 0`・`undoBase = 0`。連番は `draft.seq` から取る（`recountSeq` で記録の列を探すのはやめる）
- 開いた直後の「戻す」は何もしない（記録 10.7）

### 2.5 版

- 公開：`fold` した今の形を版にする
- 見るだけ：画面は版の今の形を土台にして描く。今の下書き（土台・`ops`・`cursor`・`undoBase`・連番）は画面の中に退避する
- この版を下書きにする：版の今の形を新しい土台にし、`ops = []`。戻す前の下書きを残すかどうかは、`fold` した今の形と公開中の版の今の形を比べて決める（6章）。「戻す」1回で置き換える前の状態（土台と `ops` と `cursor`）に戻すのは今のまま（画面の中だけ）
- 状態の文字：今の形どうしを、2.2 の決まりで並べた文字列で比べる

### 2.6 最近使った色

- 開くときに `settings` から読む。色を選んだら保存する
- 下書き・版には入れない。状態の文字にも効かない

### 2.7 記録の列をさかのぼっている所

次の所は、記録の列の中に前の操作がある前提で書かれている。**土台にある部品にも同じように効く**ようにする。ほかにもあれば足して、報告に一覧を書く。

| app.js（試験台23） | 中身 |
|---|---|
| 32 行 `secOf` | 足した部品のセクションを `add` の操作から探す |
| 1501 行あたり | 押し下げで前の `move`／`add` の操作の値を書き換える |
| 1646〜1651 行 | 足した文字の中身を `add` の操作に焼き込む（土台にある部品なら、ふつうの書き換えとして記録してよい） |
| 1802 行 | 足した部品を置き直すとき前の `add` の操作を書き換える |

### 2.8 試験用の窓口

- `ops()` は今の意味のまま（土台の後の操作）
- `draft()`：今の形を返す
- `roundTrip()`：画面を変えずに、PC とスマホのそれぞれで「土台＋記録の列から描いた形」と「`seed(fold(...))` だけから描いた形」を比べる。返すもの：部品ごとの位置・大きさの最大のずれ、片方にしかない部品、文字（切れ目の並び）・写真の ID・見せる範囲・明るさ・リンク・列・左右の入れ替えの違い

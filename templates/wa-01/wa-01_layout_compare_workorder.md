## 1. 背景

S1〜S8 で、今の自由配置は「減らす・消す」「列をまたぐそろえ」「件数の変化」で崩れた（`record_wa-01_verification.md` 7章）。直すには、テンプレートが要素どうしの関係を持つ必要がある。

一方、編集画面（`editor_prototype.html`）はオーナーが要素を自由に動かせる作りで、これは今も目指す姿である。そこで**関係の持ち方**に2つの候補があり、机の上では決めきれない。

| | 方式 A：塊の入れ子 | 方式 B：基準の木 |
|---|---|---|
| 考え方 | セクションの中を、縦積み／横並び／格子／重ねの塊で入れ子にする（Studio・Figma と同じ作り） | 各要素が縦の基準を1つだけ持つ（「見出しの下 16」「写真の縦中央 −12」）。基準は木になるので必ず解ける |
| 座標を計算するのは | ブラウザ（CSS の flex・grid・subgrid） | 自前（今の settle の実測を使って JS で計算し、絶対配置で書き出す） |
| オーナーが動かしたとき | 塊の中に落とせば「ずらし」、塊の外に落とせば「取り出し」 | 落とした場所のすぐ上の要素に基準を付け替える |

FEATURE と ITEMS の2セクションだけで両方を作り、同じ試験にかけて比べる。

## 2. 作るもの

```

  b-anchor/     方式 B：同上
  ops/          編集の操作の定義（両方式で共通の入力。3章）

  compare.mjs   両方式を同じ試験にかけ、数値と比較画像を出す
  expected-compare.json   付録 A〜C を書き起こしたもの
```

- 対象：芦屋堂の FEATURE（4.5）と ITEMS（4.6、甘味処の表・区切り線・ピルを含む全部）、PC 1440・SP 390。見出しの組（4.0）は両セクションの先頭の要素として含める
- 文字・写真・色・書体・大きさは芦屋堂の今のデータ（`samples/ashiyado`）と同じ値を使う
- SP は今と同じく、390 を基準に全体を比例で拡大縮小する
- 横の位置・幅は、どちらの方式も今と同じ持ち方（端末ごとの値）でよい。比べるのは**縦の関係**と**件数の変化**

### 2.1 方式 A のデータの形（骨組み。値は SPEC と芦屋堂のデータから）

```json
{
  "sec_feature": {
    "pc": { "type": "stack", "pad": [上, 下], "gap": ..., "children": ["grp_heading", "blk_f1", "blk_f2"] },
    "sp": { "type": "stack", ... }
  },
  "blk_f1": {
    "pc": { "type": "row", "children": ["grp_f1_text", "el_f1_photo"], "x": 160, "widths": [501, 549], "gap": 94,
            "align": "center", "alignShift": { "grp_f1_text": -12 } },
    "sp": { "type": "stack", "children": ["el_f1_photo", "grp_f1_text"], "gap": 24 }
  },
  "grp_f1_text": { "pc": { "type": "stack", "children": ["el_f1_head", "el_f1_body"], "gap": 16 } },
  "rep_cards": {
    "pc": { "type": "grid", "columns": 3, "gap": [64, 24], "rowAlign": "subgrid" },
    "sp": { "type": "grid", "columns": 1, "gap": [..., 0] },
    "card": { "type": "stack", "children": ["photo", "name", "desc", "price"], "gaps": [24, 8, 16] }
  }
}
```

- 塊の種類は4つ：`stack`（縦積み）、`row`（横並び。縦のそろえ top／center／bottom と、要素ごとのずらし）、`grid`（繰り返す部品。端末ごとの列数、`subgrid` でカードの中の同じ役割を行ごとにそろえる）、`overlay`（重ね。角と内側の距離）
- 並び順は端末ごとに持てる（FEATURE のブロック2は PC で写真が左、SP で写真が上）
- セクションの高さは中身なり（上下の余白を持つ）。消えた要素は流れから外れるので自然に詰まる
- 書き出しは CSS の flex・grid・subgrid。**配置を JS で計算しない**

### 2.2 方式 B のデータの形（骨組み）

```json
{
  "el_f1_photo": { "pc": { "x": 755, "w": 549, "h": 404, "y": { "ref": "grp_heading", "edge": "bottom", "gap": 119 } } },
  "grp_f1_text": { "members": ["el_f1_head", "el_f1_body"],
                   "pc": { "y": { "ref": "el_f1_photo", "edge": "center", "self": "center", "gap": -12 } } },
  "el_f1_head":  { "pc": { "x": 160, "w": 501, "y": { "ref": "@group", "edge": "top", "gap": 0 } } },
  "el_f1_body":  { "pc": { "x": 160, "w": 501, "y": { "ref": "el_f1_head", "edge": "bottom", "gap": 16 } } },
  "el_f2_photo": { "pc": { "x": 136, "w": 549, "h": 404, "y": { "ref": ["el_f1_photo", "grp_f1_text"], "edge": "bottom", "gap": 80 } } }
}
```

- 縦の基準は1つ。ただし `ref` に複数を並べたときは「その中でいちばん下の端」を基準にする（2列の下に続く要素のため）
- 塊（`members`）は外の要素を基準にできる。塊の中の要素が基準にできるのは、同じ塊の要素と塊の上端（`@group`）だけ。塊の中を先に組んでから、塊を置く
- 繰り返す部品は格子（端末ごとの列数、間隔）。カードの中は基準の木。**同じ行のカードの同じ役割の要素は、その行でいちばん下にそろえる**（`rowAlign: "max"`）
- **消えた要素の扱い**：その要素を基準にしていた要素は、消えた要素の基準を引き継ぐ。間隔は自分の間隔のまま（＝消えた要素の高さと、その**上の**間隔が詰まる）。先頭の要素が消えたときは、自分の高さと下の間隔が詰まる
- セクションの高さ＝中身の最も下の端＋下の余白
- 書き出しは今と同じ絶対配置。文字の高さは settle の実測を使う

### 2.3 両方式に共通すること

- 手動の記録：`overrides` の一覧に、要素・端末・性質（位置／大きさ）・値・日時を持つ（DATA_SPEC で決めた優先の規則6）
- 「自動に戻す」：要素ごとに `overrides` の行を消すと、計算どおりの位置に戻る（規則7）
- 警告：**オーナーの操作が原因の**重なり・はみ出しを一覧で出す。勝手に直さない（規則3）。テンプレートどおりの状態で出ていない重なりだけを数える

## 3. 編集の操作（両方式に同じ入力を与える）

操作は「画面上で何をしたか」で定義する。各方式は、それを自分のデータに翻訳する。

| 操作 | 入力 | 方式 A の翻訳 | 方式 B の翻訳 |
|---|---|---|---|
| move | 要素、端末、落とした位置（セクションの中の x, y） | 元の塊の範囲の中なら「ずらし」（dx, dy。塊の中の場所は残る）。外なら「取り出し」（セクションの座標。跡は詰まる） | 落とした位置のすぐ上にあり横の範囲が重なる要素（なければ見出しの組）に基準を付け替え、間隔を記録。この要素を基準にしていた要素は、元の基準を引き継ぐ |
| resize | 要素、端末、幅・高さ | 固定の大きさにする（塊の中に残る） | 固定の大きさにする |
| add | 種類、中身、端末、置いた位置 | セクションの座標の自由な要素（流れに入らない） | 置いた位置のすぐ上の要素を基準にする |
| remove | 要素 | 「消した」印。流れから外れる | 「消した」印。2.2 の消えた要素の扱い |
| reset | 要素 | その要素の `overrides` を消す | 同じ |
| editRow | 繰り返す部品、カードの中の要素、性質と値 | 1行の作りを変える（全行に効く） | 同じ |

## 付録 A　共通の決まり

- 位置は、特に書かない限り**セクションの上端から**。PC は 1440、SP は 390 で測る
- 許容差：位置 ±2、大きさ ±2、関係 ±2。「変わらない」は ±0.5
- 「以下」とは、そのセクションの中で対象より下にある全要素と、セクションの下端
- 行送りは本線のとおり（本文 16／28.8、SP 14／25.2、品の説明 14／22.4）。「1行増える」は行送りの分だけ高くなることを指す
- S4 の格子の行の間隔（PC 64）は SPEC にない値で、Claude.ai がこの比較のために決めた暫定値

## 付録 C　編集を想定した試験

操作は3章の定義どおりに与える。「→」の後が、操作の後に続けて行う中身の変化。

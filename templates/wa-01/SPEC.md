# wa-01 設計書（SPEC v2）

これまでの `templates/wa-01/SPEC.md` を**全面的に置き換える**。v1 は参照元の数値を十分に引き継がず、色・書体を選び直したため、見た目の質が参照元に届かなかった。v2 は、参照元を PC（幅1440）とスマホ（幅390）で実測した値を、そのまま芦屋堂の配置に落としたもの。

- 参照元：https://preview.studio.site/templates/Q65qmmvqVR（日本茶ブランドの商品紹介ページ）
- 実測日：2026-09-22（Chrome で計測。値は px、y はセクションの上端からの距離）
- 書いた人：Claude.ai（分析・指示書）／組み立て：Claude Code

---

## 0. この設計書の読み方と、守ること

1. **数値は目安ではなく仕様**。4章以降の表の値に合わせる。許容差は 10章。
2. 表に書いていない値を決めるときは、**同じ設計書の中の似た箇所の値を使う**（例：新しい見出しは、他のセクションの見出しと同じ大きさ・同じ上端からの距離）。新しい値を発明しない。
3. 迷ったら、推測で進めずに参照元を開いて同じ箇所を測る。
4. 参照元から**持ち込まないもの**は 11章。写真・文章・ロゴ・店名は一切使わない。
5. 座標の変換：データの `layout.pc.x`・`w` は **px ÷ 1440 × 100**（％）、`layout.sp.x`・`w` は **px ÷ 390 × 100**。y・h・文字の大きさは px のまま。`canvas.pcContentWidth = 1440`、`canvas.spDesignWidth = 390`。

## 7. 写真の枠と選び方

### 7.1 全体の基準（全枠共通）

- **トーン**：参照元と同じく、暗めの背景・低い照度・深い影・彩度は控えめ。室内の静物が中心。屋外は**枠B〜Dのうち1枚まで**と**枠K**だけ（どちらも彩度の低い、細部の少ないもの）。
- **全枠でそろえる**：光の向き（片側からの自然光）、色の温度（やや暖かいが黄色すぎない）、黒のしまり。1枚だけ明るい・青い、を作らない。
- **写してはいけないもの**：顔、人の姿（手元は可）、文字（看板・のれんの店名・ロゴ・包装の印字・寺社の印）、明らかに海外の店や洋菓子。
- **参照元で使われている写真は使わない**（参照元の写真も Unsplash のもの。同じ写真にしない）。
- **品の写真はその品を写したもの**（既存の規則どおり）。
- 解像度：枠の表示幅の2倍以上。
- 1つのページで同じ写真を2回使わない。

## 8. 文章（芦屋堂の全文）

原則：**①に書かれた事実だけを使う**。サンプルの店なので、足したい事実はまず①に入れてから文章に使う（下の「①に足すもの」）。お店の人のメモ（story.answers）はそのまま本文に出さない。

### 8.1 ①に足すもの（samples/ashiyado/shop.json）

- 品の説明：
  - どら焼き：「ふっくら焼いた皮に、自家製の粒餡をはさみました。」
  - 芦屋最中：既存の「香ばしい皮に、つぶ餡をたっぷり。」のまま
  - わらび餅：既存のまま
- FAQ を1件追加：質問「予約はできますか？」／答え「上生菓子は前日の17時までにお電話でご予約いただけます。」（① reservation.note と同じ事実）
- おすすめのラベルは 4.6 の規則で付け替える。

### 8.2 各所の文章

- **FV**：「季節を映す、／ひと口の和菓子」／「ASHIYA WAGASHI SINCE 1978」
- **ABOUT のリード**：「朝炊く餡を、その日の分だけ。」
- **ABOUT の本文**：
  > 1978年、父の代にはじまった芦屋の和菓子店です。店主は京都の老舗で修業ののち、地元の芦屋に戻りました。餡は毎朝炊き、その日にお出しする分だけをつくります。上生菓子はひと月ごとに入れ替わり、その月にしか出会えない菓子が店先に並びます。
- **FEATURE 1**（季節の上生菓子）：
  > 練り切りときんとんの意匠は、ひと月ごとに変わります。季節の移ろいを、小さな菓子に写してお届けします。
- **FEATURE 2**（店の奥の、甘味処）：
  > 店の奥の8席で、わらび餅や抹茶をお召し上がりいただけます。わらび餅は本わらび粉を使い、ご注文ごとに切り分けます。

## 9. データへの落とし方（Claude Code 向けの要点）

1. `canvas.pcContentWidth = 1440`、`spDesignWidth = 390`。座標は 0章5 の式で％にする。
2. 見出しの組（4.0）は各セクションで同じ値。コピーで作ってよいが、値がずれていないことを 10章の照合で確かめる。
3. ABOUT の写真の帯は、繰り返す部品ではなく**3つの写真要素**で作る（`fullBleed`、x は負の値・100%超を使う）。
4. 甘味処の表・お品書きの表は、繰り返す部品の `display.mode = "list"` で、カードの設計に罫線（図形の線）と縦の罫線を含める。
5. 価格の書き方「380円（税込）」は format の追加（例 `priceAllTax`）で行う。schema・validate・DATA_SPEC をそろえる。
6. v1 で足した `marquee` の指示は取り消す（参照元の帯は動かない）。もし足してあれば、使わないまま残すか外すかを報告する。
7. 重なり・はみ出しの検査：セクションで切り取られて見えない部分は「はみ出し」に数えない。
8. 書き終えたら settle → validate → build → check。

## 10. 受け入れ基準と照合の手順

### 10.1 数値の照合（機械）

- この設計書の 4〜6章の表を `templates/wa-01/expected.json`（要素のID → PC・SP の x, y, w, h、文字の大きさ・太さ・書体・色）に書き起こし、書き出したサイトの実際の値と比べる道具を作る（`npm run spec-check`）。
- 許容差：位置 ±4px、大きさ ±2px（写真の枠・ボタン・線）、文字の大きさ・太さ・書体・色は**完全一致**。「自動」「中身に合わせる」とした高さは照合しない。
- 1440・390 の両方で、全要素が許容差に入ること。入らない要素は理由を添えて報告。

### 10.2 見た目の照合（人の目に近い確認）

- 参照元と芦屋堂を、同じ幅（1440・390）で**セクションごとに左右に並べた比較画像**を `refs/compare/` に作る（縮小してよい）。この工程は画像を見てよい。
- 見るのは：余白の量、写真の大きさと位置、文字の大きさの比、色の明るさ、写真のトーンのそろい方。
- 比べてずれがあれば、数値で原因を特定して直す。直したら撮り直して再照合。

### 10.3 既存の検査

- check（3エンジン × 全ページ × 5幅）：想定外の重なり0、はみ出し0（切り取られた部分を除く）、実測ずれ2px以内。

### 10.4 報告

- spec-check の結果（許容差外の要素の一覧と理由）
- 比較画像で見つけて直したこと、残したことと理由
- 選んだ写真（枠・撮影者・URL・理由）
- check の結果

## 11. 参照元から持ち込まないもの

- 写真（参照元の写真と同じ写真も使わない）、文章、ロゴ（「Brand.」と丸い印）、商品名・価格・住所。
- 持ち込んでよいもの：構造の数値（位置・大きさ・余白）、色の値、書体、文字の段、罫線や横棒・ピルのボタンのような一般的な形。
- 理由：灰色の階調・無料の書体・一般的な形は、それ自体が誰かの権利の対象ではなく、写真・文章・店名が違えば複製にはならない。一方、値を選び直すと参照元の質が失われる（v1 の反省）。

## 1. 写真の差し替え（PowerPoint の「図の変更」と同じ）

### 1.1 やり方（3つ）

| やり方 | 操作 |
|---|---|
| 選ぶ | 写真を右クリック → 操作ボタンの「写真を差し替える」→ ファイルを選ぶ画面 |
| 落とす | 画像ファイルを、写真の枠の上に落とす。落とせる間は、枠を色で縁取る |
| 貼り付ける | 写真を選んだ状態で、画像を貼り付ける（Cmd+V・Ctrl+V） |

- 写真の入っていない枠（「写真を外す」の後）にも、同じ3つで入れられる。入れたら外した印は消える
- 品の写真（品の1件の中の写真）も、1件ずつ同じやり方で差し替えられる。品の位置は動かない（2.10 のまま）
- 写真以外を選んでいるときの画像の貼り付け、写真の枠の外に落とした画像は、**今回は何もしない**（写真を足す操作は別の回で）

### 1.2 振る舞い

- **枠の大きさ・位置は変わらない**。周りの部品も動かない（PowerPoint の「図の変更」と同じ）
- 新しい写真は、枠いっぱいに、はみ出す所を切って入れる（隙間を作らない）。見せる範囲は真ん中・1倍から始める
- 縦横の比が枠と違う写真でも同じ（横長の写真を縦長の枠に入れたら、左右が切れる）
- **写真は PC とスマホで共通**（中身は共通、6.5）。片方で差し替えたら両方変わる
- 大きな写真は、読み込むときに**長い辺 2400px まで縮めて**持つ（画質 0.85 程度の JPEG）。小さい写真は縮めない
- 向きの情報が付いた写真（iPhone の縦写真など）は、**正しい向き**で扱う
- 読めないファイル（画像でないもの、ブラウザが開けない形式）は、何も変えずに、枠の近くに「この写真は読み込めません」とだけ短く出す（数秒で消す）。画面に出す言葉は、これだけ

### 1.3 記録

- 写真の中身として、素材の ID を持つ（今回の試験台では、読み込んだ画像を、ページの中だけで持つ。保存はしない）
- 差し替えは「戻す」「やり直す」で1回ずつ戻る
- 「元の位置に戻す」では、写真は戻らない（中身なので。4.2 のまま）

## 2. 見せる範囲（PowerPoint の「トリミング」と同じ）

### 2.1 やり方

- 写真を**ダブルクリック**（または操作ボタンの「見せる範囲」）で、見せる範囲を変える状態に入る
- その状態では、**枠の外にはみ出している画像の部分も薄く見せる**（どこを切っているか分かるように）
- **画像をドラッグ**して、見せる位置を動かす
- **画像の四隅のつまみ**で、画像を拡大・縮小する（比は保つ）。マウスのホイールでも拡大・縮小できる
- **Enter か、枠の外を押して決める**。**Esc で取り消す**（始める前の見せる範囲に戻る）

### 2.2 決まり

- **枠に隙間ができるところまでは動かせない・縮められない**（画像はいつも枠を覆う）。そこで止まる
- 拡大は 1倍（枠を覆う一番小さい大きさ）から 4倍まで
- 枠の大きさ・位置、周りの部品は変わらない
- 見せる範囲は**端末ごと**に持つ（枠の形が PC は横長、スマホは縦長と違うため）
- ただし、**まだ触っていない方の端末は、触った方の主役の位置（見せる位置）を引き継ぐ**（拡大は 1倍のまま）。片方で決めれば、もう一方もだいたい合う。もう一方で一度でも決めたら、そこからは別々
- 差し替えたら、両方の端末の見せる範囲は真ん中・1倍に戻る
- 1回決めるごとに、「戻す」で1回戻る
- 「元の位置に戻す」では、見せる範囲は戻らない（中身として扱う）

### 2.3 記録

- 見せる範囲は、写真の中身として、端末ごとに `{x, y, zoom}` で持つ。`x`・`y` は、枠の真ん中に来る画像の点を、画像の幅・高さに対する割合（0〜1）で表したもの。`zoom` は 1〜4
- 触っていない端末は持たない（引き継ぎで決まる）

## 3. 入口

`window.__playground.photos()` で、今の端末の写真の状態を返す。

```
[{part, asset, naturalW, naturalH, cleared, view: {x, y, zoom}, viewOwn: true|false}]
```

- `asset`：素材の ID（テンプレートの写真は今の ID のまま。差し替えたら新しい ID）
- `naturalW`・`naturalH`：持っている画像の大きさ（縮めた後。向きを直した後）
- `viewOwn`：この端末で見せる範囲を決めたか（false なら引き継ぎか、真ん中・1倍）
- 品の写真も含める（`part` は品の写真の部品 ID）

## 5. 試験（本物のマウス・キーボードの操作で。PC とスマホの両方）

ファイルを選ぶ画面は OS のものなので、試験では、**操作ボタンで開く `<input type="file">` にファイルを渡す**形でよい。落とす・貼り付けるは、**写真の枠に、ファイル付きの drop・paste の出来事を送る**形でよい。これは操作の置き換えではなく、この作業票で決めた試験の仕方とする。

| # | 操作 | 確かめること |
|---|---|---|
| P1 | 特集1の写真を右クリック →「写真を差し替える」→ `wide.jpg` | 枠の位置・大きさが変わらない（±0.5）。周りの部品が動かない。`photos()` の `asset` が変わり、`view` は真ん中・1倍。枠の左上の角の近くが赤、右下の角の近くが黄 |
| P2 | 特集1の写真を `tall.jpg` に差し替える（P1 と同じやり方） | 枠は変わらない。枠の四隅の近くが、それぞれ赤・緑・青・黄（隙間がない） |
| P3 | `wide.jpg` を、特集2の写真の枠の上に落とす | P1 と同じ（特集2の写真で） |
| P4 | 特集1の写真を選び、`small.png` を貼り付ける | 差し替わる。`naturalW` 300（縮めない） |
| P5 | 特集1の写真を「写真を外す」→ その空の枠に `wide.jpg` を差し替える | 写真が入る。`cleared` が false。枠の大きさは外す前と同じ |
| P6 | 品の1件目（わらび餅）の写真に `tall.jpg` を落とす | その品の写真だけ変わる。ほかの品の写真は変わらない。品の位置は動かない |
| P7 | 特集1の写真をダブルクリック → 画像を右へ 100 ドラッグ → Enter | `view.x` が減る（左側が多く見える）。`viewOwn` true。枠と周りは動かない |
| P8 | 特集1の写真をダブルクリック → 画像の右下のつまみを外へ動かして 2倍にする → Enter | `view.zoom` が 2（±0.05） |
| P9 | 特集1の写真をダブルクリック → 画像を右へ 5000 ドラッグ → Enter | 枠の左端で止まる（`view.x` が下限）。枠の左上・左下の角の近くが、赤・青（隙間がない） |
| P10 | P7 の操作を、Enter ではなく Esc で終える | `view` が始める前と同じ |
| P11 | PC で P7 を行い、スマホに切り替える。続けてスマホで画像を下へ 50 ドラッグして決め、PC に戻す | スマホに切り替えた時点で、スマホの `view.x`・`view.y` が PC と同じ、`zoom` 1、`viewOwn` false。スマホで決めた後、PC の `view` は P7 のまま |
| P12 | P1 の後に P7、続けて「戻す」2回、「やり直す」2回 | 戻す1回目で見せる範囲が戻り、2回目で写真が元に戻る。やり直すで順に P1・P7 の状態 |
| P13 | `big.jpg` に差し替える | `naturalW` 2400・`naturalH` 1600 |
| P14 | `rotated.jpg` に差し替える | `naturalW` 1200・`naturalH` 1600。枠の左上の角の近くが赤 |
| P15 | `notimage.txt` を差し替えに使う | 写真は変わらない。「この写真は読み込めません」が出て、数秒で消える |
| P16 | 特集1の写真の大きさを変え（Y7 と同じ）、その後に `wide.jpg` に差し替える。続けて「元の位置に戻す」 | 差し替えても、変えた大きさのまま。「元の位置に戻す」で大きさは戻るが、写真は `wide.jpg` のまま |

P1・P2・P7・P8・P9・P11 は、操作の前と後の画像を出す（PC とスマホ）。P7 は、見せる範囲を変えている途中（はみ出した部分が薄く見えている所）の画像も出す。

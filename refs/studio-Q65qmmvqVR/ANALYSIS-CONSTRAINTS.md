# 参照元の分析の道具の制約（clone §2.1 で判明）

- 参照元 https://preview.studio.site/templates/Q65qmmvqVR は、**全面ヒーロー写真を Studio の描画層（render-canvas / StudioCanvas＝WebGL）で描いている**。
- そのため DOM には対応する `<img>`・背景 url()・`<canvas>` タグ・`<video>` が無く、`ref-mask.mjs` の DOM 置換では灰色に覆えない（カード写真＝light-DOM の `<img>` は覆える）。
- **これは「表示の仕組み（芦屋みっけ側）の限界」ではなく、「参照元を分析する道具の制約」**。clone-gaps.md には書かない。
- 対処（§2.3）：画素比較は、取得済みの幾何から写真の矩形を出し、**参照元の撮影画像と再現の撮影画像の両方に同じ #9A9A9A 矩形を塗ってから** pixelmatch にかける（`tools/clone-compare.mjs`）。両方に同じ処理＝条件がそろう。塗った矩形と塗った面積の割合を結果に記録する。

## WebGL 写真は FV ヒーローだけではない（2026-09-23・全セクション画素比較で判明）
- 全セクションの画素比較（`tools/clone-pixel.mjs`）を回したところ、**ABOUT（セクション下部の全幅3枚組ギャラリー）と CONTACT（セクション背景の全面写真）にも同じ WebGL 層の写真がある**ことが分かった。いずれも DOM に img・背景 url() が無く、`ref-mask.mjs` では灰色に覆えず、COLLECT の幾何にも出ない。
- **これは再現（仕組み）側の不足ではなく道具側の穴**（要素の照合は PC/SP とも全セクション ✓〔ロゴ等の例外を除く〕）。

## 覆えない写真は固定値でなく機械的に検出する（b2・2026-09-23）
`clone-pixel.mjs` は「覆えない写真の矩形」を固定値で持たず、参照元の撮影画像から機械的に求める：
- **検出規則**：覆った参照元で「DOM から取れた要素（文字・図形・写真）が1つも重ならず、かつ単色でないマス（8px 格子）」の連結塊の外接矩形＝覆えない写真の領域。単色判定は「輝度レンジが小さく、かつ平均色が無彩色」（覆いの地は白/#EEE/灰/#333 等の無彩色パレット、実写だけが有彩色 or 高レンジ。暗く滑らかな実写＝FV の茶器も暖色なので拾える）。
- **背後の単色 div は覆いに数えない**：FV スクリム #000・CONTACT 地 #333 は WebGL 写真の背後に敷かれた全面 div。これを覆いに数えると手前の実写を検出できないので、全幅かつ高さのある面（w≥1400・h≥300）はコレクション時と同様に覆いから除く。
- **出力**：検出した矩形の一覧（セクション・座標・大きさ・面積割合）を毎回レポートに出す（`refs/compare/clone-pixel-report.json` の `autoRects`、および実行時のログ）。
- **40% 規則**：塗った面積がセクションの 40% を超えたセクションは「画素比較は成立しない（合否を出さない）」＝要素の照合で判定する。現状 **FV（97%）・CONTACT（100%）が無効**、ABOUT（39.6%）・FEATURE・PRICE・FAQ・FOOTER は有効。
- 機械検出で拾えた実測矩形（2026-09-23）：FV 全幅×720（ヒーロー）／ABOUT 全幅×約424 のギャラリー3枚／CONTACT 全幅×約600（背景）。固定値ではないので参照元を撮り直せば追従する。
- SP でも同種の写真が出るが、SP の画素比較は今回範囲外（`clone-pixel` は PC のみ／SP は要素の照合で判定）。SP に広げる場合も同じ機械検出が使える。

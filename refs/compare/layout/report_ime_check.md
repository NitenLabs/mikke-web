## 5. 気になったこと（直していません・判定でもありません）

1. **変換中、モデル側の配置は凍る／しかし文字箱の“素の伸び”で同じ組の部品が動く。**
   - 変換中は `ops()`＝0・セクション高・ページ高が不変（＝配置の計算・流し直しはしていない）。一方で、ブラウザが変換中の文字を文字箱に描くぶん**箱の高さが伸び**、同じ組の部品が動く（PC：見出し・本文が上へ 14.36px／スマホ：下の組が下へ 25.19px）。8.3 の「画面の組み直しをしない」を部品の見た目の位置まで含めて読むと差が出る所。セクション・ページの寸法は凍っている。Claude.ai の判断用に数値を置く。
2. **I3：Esc は「変換の取り消し」ではなく「書き換えの確定・終了」になった。** 変換中の読み「かし」が消えずに残り、書き換えが終わる（`editingId`＝null）。ページが keydown の Escape を `commitEdit` に割り当てているため、ブラウザの変換取り消しより先に確定した。続けての2回目の変換は（書き換えが終わっているので）入らなかった。
3. **I7：自動保存は「書き換えの確定（op）」に紐づく。** 変換中はもちろん、書き換えを開いている間は `lastSavedAt` が動かない。読みの文字が下書きに保存されることはない。
4. **I4：1回の書き換えセッションは1まとまりの取り消し単位。** 5語を続けて決めても、Cmd+Z 1回で全部戻る。変換の途中（読み）の文字は取り消し途中に一切現れない。
5. **記録 8.3 の所在：** 作業フォルダの `record_layer3_editing_rules.md` は全11章で、その 8.3 は「もう一方の端末で自動配置された位置は手動扱いしない」＝**日本語入力の 8.3 とは別内容**（10.1・14・15 も同書には無い）。作業票が指す「記録 8.3／10.1／14／15」は、この作業フォルダの版とは別（新しい版）と思われる。該当章の原文には当たれていない。

## 6. B（Mac の本物の日本語入力）の詳細

- **前提（§4.1）は両方そろっていた：** 日本語入力ソース `com.apple.inputmethod.Kotoeri.RomajiTyping`（Japanese モード）あり／`osascript ... keystroke ""` が exit 0（アクセシビリティ許可あり）。
- **安全の決まりは守った：** 最前面アプリを毎キー前に確認（＝`Google Chrome for Testing`。一度も別アプリに変わらず、中止せず）。入力ソースは実行後に元へ戻した（`restored_ok: true`、現在 `com.apple.keylayout.ABC`）。試験台22 のコードは不変。
- **結果：信号がページに届かなかった。** `osascript` の System Events `keystroke`／Ctrl+Space を送ったが、
  - 本文の文字は変化せず（「…お届けします。」のまま）、composition イベントは `[]`（画面の写し `B_I1_composing.png`＝書き換えの枠は青いが変換中の文字も候補窓も無し）。
  - Ctrl+Space による入力ソース切替も効かず（切替後も ABC のまま）。
- **解釈（判定ではない）：** Playwright 制御下の Chrome（`Google Chrome for Testing`）の Web コンテンツに、OS レベルの AppleScript keystroke が届いていない模様。§0 のとおり別の送り方に置き換えず、ここで止めて報告する。別の方法（`cliclick` 等の導入や送信先の変更）を試すかは、指示を待つ。

## 7. C（iPhone の下調べ・調べのみ）

- **Xcode／iOS シミュレータ：なし。** `xcrun simctl` が「unable to find utility "simctl"」＝**Command Line Tools のみ**（`/Library/Developer/CommandLineTools`）で、完全版 Xcode が無いためシミュレータを起動できない。
- **Playwright WebKit：いまのままでは起動不可。** キャッシュに `webkit-2359` はあるが、今の Playwright が要求するのは `webkit-2287`＝版の不一致（`playwright install webkit` が必要。今回は入れていない）。
- **記録 14.10（iPhone の Safari）の見立て：**
  - **ケーブルなしで難しい／実機でないと無理：** iOS の**ソフトウェアキーボード**と**日本語変換（候補バー・確定の挙動・変換中のレイアウト）**。これは iOS 実機（または最低でもソフトキーボードを持つ完全な iOS シミュレータ）が要る。A で使った CDP `Input.imeSetComposition` は **Chromium 専用**で、WebKit/Safari では同じ手は使えない。
  - **ケーブルなしでも近いことは見られる（ただし Safari そのものではない）：** `playwright install webkit` を入れれば、WebKit エンジンでの**レイアウト・幾何（部品位置・セクション高）**や、JS から起こせる範囲の挙動は見られる。ただし iOS のソフトキーボード/IME は再現されず、**本物の変換中の挙動は WebKit-on-mac では確認できない**。
  - **結論の見立て：** 8.3 の iPhone 確認は、**実機 iPhone（Safari）での目視**が本筋。シミュレータを使うにも完全版 Xcode の導入が要る（今回は導入判断を保留）。

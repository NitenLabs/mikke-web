## 1. §1 の見立ての確認（本当の原因）

**見立ては、ほぼそのとおりでした。** コードを読んで確かめた原因は次のとおりです。

- 23b で `undo`/`redo` が **区切りの edit op（`_ses`）を戻す/進めるたびに `reenterEditSession` で書き換えに入り直す**ようになった（`app.js`）。
- 「文字の見た目を元に戻す」は `resetTextStyle(id)` → `commit({t:"tstyleReset", …})`。これは **書き換えを終えずに** op を積んで `render()` するだけ。
- ところが `textRunsApi(part)` は **書き換え中（`state.editing.id===part`）だと `state.editing.runs` を返す**（`app.js` 現 408 行付近）。入り直した書き換えが持っている runs は**赤つきの古いまま**なので、`tstyleReset`（reduce では `runsMap[part]` を消す）を積んでも、読み取りは赤つきの `editing.runs` を返す＝**元に戻しが反映されない**。その後に書き換えを終えると、その赤つき runs が確定し直して**上書き**される。
- 試験台22 では `undo`/`redo` のあと書き換えは終了していた（`editing=null`）ので、`resetTextStyle` は「書き換えていない部品」に効き、赤が消えて通っていた。つまり **23b の入り直しが引き金**で、環境差ではない（§1 の判定と一致）。

## 2. 直したところ

### X35（書き換えの外からの操作は先にふつうに終える）

- **`app.js` `resetTextStyle(id)`**：書き換え中なら **先に `commitEdit()`**（書き換えの外をクリックしたときと同じ）してから `tstyleReset` を積む。これで入り直した書き換えでも、生きている runs を確定させてから元に戻すので、`textRunsApi` が古い赤を返さない。入り直しかどうかに関わらず効く。
- **`build.mjs` の右クリック（`contextmenu`）ハンドラ**：メニューを出す前に、書き換え中なら **先に `commitEdit()`**。これで右クリックメニューの全項目（元に戻す・前面/背面・複製・削除・列・リンク）とセクションのメニューが「書き換えの外をクリックと同じ」挙動になる。元ノードが `render` で外れても困らないよう、部品 ID は終える前に取っておく。
- **部品の移動・大きさ**は、すでに `build.mjs` の `pointerdown`（`if(PG.state.editing) PG.commitEdit();`）で先に終えている＝X35 の決まりを満たしていたので、変更なし（K3 で確認）。**箱まるごとの見た目**（書体・大きさ・色の箱全体）も、すでに `beforeTs()` が `commitEdit()` してから効かせているので変更なし。
- **選んだ文字に道具（太字・色など）を使う操作は変えていない**（`applyPartStyle` 系）。書き換えの中で効く＝D 系の形を崩さない（K4 で確認）。

### X34（戻すものが無いときは何もしない）

- **`app.js` `undo()`**：`state.cursor <= state.undoBase`（＝これ以上戻すものが無い。開き直した後の undoBase 床も含む）のとき、**何もせず return**。以前は `if (state.editing) endEditSilently();` で書き換えを終えていた（＝「文字は変わらないのに書き換えが終わる」）のを外した。書き換えの状態もカーソルの位置もそのまま。
- `redo()` は元から「やり直すものが無ければ早期 return（書き換え・カーソルそのまま）」で、X34 の求める挙動を満たしていたので変更なし（K7 で確認）。

## 5. 気になったこと（直していません・判定でもありません）

1. **K2 の「元に戻すを戻すと赤が戻る」ときの書き換えの状態は `None`**。`tstyleReset` は `_ses` でない普通の op なので、それを `undo` しても書き換えには入り直さない（入り直すのは文字の区切り＝edit op だけ）。赤は runs に戻るが、カーソルは置かれない。意図どおりと思うが、判定は Claude.ai に委ねる。
2. **K3 で「春」を入れてから入り直し→移動すると、移動の時点で `春` の区切り op が捨てられる**（戻した後に新しい操作をしたので、やり直しの先が切れる＝PowerPoint と同じ）。本文が original のまま dx だけ入るのはそのため。
3. 右クリックの前に `commitEdit()` を入れたことで、`render()` が走って元ノードが差し替わりうる。部品 ID はクリック時点で取ってから終えるようにしたが、セクションの余白を右クリックする経路は、もともと `pointerdown` が先に書き換えを終えているので二重の `commitEdit()` は無害（`state.editing` が無ければ即 return）。

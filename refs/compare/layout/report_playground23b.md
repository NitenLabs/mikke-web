## 1. 直したところ（playground23）

一度の書き換えを「区切り（checkpoint）」の列として記録し、Cmd+Z は区切りごとに戻す。区切りは **edit op（`_ses` 印つき、カーソル位置 `editCaret` つき）** として ops に積むので、**書き換えを終えた後も同じ細かさで戻せる**（まるごと1つにまとめ直さない）。

- **区切りを作る所（`flushCheckpoint`）**
  - **日本語の変換を1回決めたら1回**（`compositionend`。要素の `oncomposition*` が届かない経路の保険として **document でも `compositionstart/compositionend` を監視**し `imeBoundary()` を呼ぶ）
  - **変換を使わずに打った分で1回**。空白・句読点（、。，．・,.!?！？;:）・改行を打つ／**打つ↔消すの切り替え**／**カーソル移動**（矢印・Home/End）／**1秒止まる**で区切る
  - **消す（Backspace・Delete）も続けて消した分で1回**（区切り方は打つときと同じ）
  - **文の一部の見た目（太字・色・大きさ・書体・リンク）を変えたら1回**（`applyPartStyle`）
- **戻す／やり直し（`undo`/`redo`）**：区切りの edit op を1つ戻す/進めるたびに、**書き換えの状態に入り直し、戻した所（差分の位置）にカーソルを置く**。書き換えでないときに戻しても入り直す。Cmd+Shift+Z も同じ細かさ。
- **変換中の文字は戻すの対象にしない**（23a の X33。`composing` 中は区切らない）。
- 足したばかりの文字（`pendingNewText`）は従来どおり add に焼き込む（1追加=1undo）。

## 5. 気になったこと（直していません・判定でもありません）

1. **変換の確定イベントが、要素の `oncomposition*` ハンドラに届かない経路があった**（CDP の `imeSetComposition`／`insertText` では要素の `oncompositionstart/end` が発火せず、`document` レベルのリスナ（capture）には届く）。そこで **document でも変換の境目を監視**して区切るようにした（要素ハンドラと二重になっても2回目は何もしない＝無害）。本物の IME でも document 監視で確実に区切れる。
2. **CDP の `Input.insertText` は `compositionend` を出さない**ため、U1・U4・U5 の「1変換の確定」は、本物の IME と同じく確定イベント（`compositionend`）を明示的に発火して再現した（変換の信号自体は 23a と同じ CDP）。
3. 区切りの付け方（空白・句読点を**打った分に含める**か**次の区切りの頭にする**か）は、今回「打った分に含める」（例：U2 の「abc 」）。記録 0.6 の範囲で決め方を1つ固定した。
